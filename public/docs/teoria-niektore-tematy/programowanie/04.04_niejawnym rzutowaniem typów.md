# Niejawne rzutowanie typów (implicit type conversion)

## Czym jest rzutowanie typów?

**Rzutowanie typów** to zamiana wartości jednego typu na wartość innego typu. W C++ (i Arduino) istnieją dwa rodzaje:

- **Jawne (explicit)** — programista sam wskazuje, że chce zmiany typu: `(int) 3.7`
- **Niejawne (implicit)** — kompilator wykonuje zamianę automatycznie, bez żadnej instrukcji od programisty

Ten dokument skupia się na **niejawnym** rzutowaniu, bo właśnie ono jest źródłem błędów, które trudno dostrzec gołym okiem.

---

## Jak działa niejawne rzutowanie?

Kompilator C++ stosuje niejawne rzutowanie zawsze wtedy, gdy po obu stronach operacji lub przypisania są **różne typy danych**. Robi to według ustalonych reguł, wybierając tzw. *typ wspólny* (common type).

### Ogólna zasada: "mniejszy" typ przechodzi w "większy"

```
bool → char → int → long → float → double
```

Gdy dwa typy trafiają razem do operacji, słabszy (mniej pojemny) zostaje automatycznie poszerzony do silniejszego.

---

## Przykłady niejawnego rzutowania

### 1. int → float przy przypisaniu

```cpp
int a = 5;
float b = a;   // int zostaje zamieniony na float: b == 5.0
```

Nic groźnego — żadna informacja nie ginie.

---

### 2. float → int przy przypisaniu (UWAGA: utrata danych!)

```cpp
float x = 3.99;
int n = x;      // n == 3 — część dziesiętna jest obcinana, NIE zaokrąglana!
```

Kompilator nie zgłosi błędu ani ostrzeżenia. Wartość `3.99` cicho staje się `3`.

**Na Arduino to częsty błąd:** odczyt z czujnika (float) wpisany do zmiennej `int` traci precyzję.

---

### 3. Mieszanie typów w wyrażeniu arytmetycznym

```cpp
int a = 7;
int b = 2;
float wynik = a / b;   // wynik == 3.0, NIE 3.5 !
```

Dlaczego? Bo `a / b` to **dzielenie całkowite** (oba operandy to `int`). Wynik `3` dopiero *potem* jest zamieniany na `float 3.0` przy przypisaniu — ale jest już za późno.

Żeby dostać `3.5`, trzeba wymusić dzielenie zmiennoprzecinkowe:

```cpp
float wynik = (float)a / b;   // jawne rzutowanie jednego operandu
// lub:
float wynik = a / 2.0;        // literał 2.0 jest double → a zostaje podniesiony
```

---

### 4. char i int — znaki jako liczby

```cpp
char litera = 'A';
int kod = litera;    // kod == 65 (kod ASCII litery A)
```

`char` jest traktowany jak mała liczba całkowita. W C++ (i Arduino) `char` to po prostu 8-bitowa liczba.

```cpp
char litera = 'A';
Serial.println(litera + 1);   // wypisze 66, nie 'B'
```

Jeśli chcemy wypisać `'B'`, trzeba jawnie rzutować: `Serial.println((char)(litera + 1));`

---

### 5. bool → int

```cpp
bool flaga = true;
int n = flaga;    // n == 1

bool off = false;
int m = off;      // m == 0
```

I odwrotnie — dowolna niezerowa liczba całkowita zamieniona na `bool` daje `true`:

```cpp
int x = 42;
bool b = x;   // b == true

int y = 0;
bool c = y;   // c == false
```

---

### 6. Przepełnienie przy przypisaniu do węższego typu

```cpp
int duza = 300;
byte mala = duza;   // byte mieści 0–255; mala == 44  (300 - 256 = 44)
```

Wartość "owija się" modulo 256. Kompilator może nie zgłosić żadnego ostrzeżenia.

---

### 7. Niejawne rzutowanie w warunkach

```cpp
int sensor = analogRead(A0);   // wartość 0–1023

if (sensor) {           // int zamieniany na bool: 0 == false, reszta == true
    digitalWrite(LED_BUILTIN, HIGH);
}
```

To działa poprawnie i jest idiomem C/C++, ale trzeba wiedzieć, co się dzieje pod spodem.

---

## Tabela najważniejszych przypadków

| Skąd | Dokąd | Co się dzieje |
|------|-------|---------------|
| `int` | `float` | bezpieczne poszerzenie |
| `float` | `int` | **obcięcie części dziesiętnej** (nie zaokrąglenie!) |
| `int` | `byte` | **przepełnienie** jeśli wartość > 255 |
| `char` | `int` | zamiana znaku na kod ASCII |
| `bool` | `int` | `true` → 1, `false` → 0 |
| `int` | `bool` | 0 → `false`, niezerowe → `true` |
| `double` | `float` | możliwa utrata precyzji |

---

## Praktyczny przykład na Arduino

```cpp
// Czytamy napięcie z potencjometru i chcemy procent (0–100)

void setup() {
    Serial.begin(9600);
}

void loop() {
    int raw = analogRead(A0);     // 0–1023

    // BŁĄD: niejawne rzutowanie ukrywa problem
    int procent_zly = raw / 10.23;   
    // raw (int) dzielone przez 10.23 (double) → raw zostaje zamieniony na double,
    // wynik double → przypisany do int → obcięcie

    // LEPIEJ: jawnie panować nad typami
    float procent_ok = (float)raw / 1023.0 * 100.0;

    Serial.print("Zły sposób: ");
    Serial.println(procent_zly);

    Serial.print("Dobry sposób: ");
    Serial.println(procent_ok, 1);   // 1 miejsce po przecinku

    delay(500);
}
```

---

## Jak unikać problemów?

1. **Zwracaj uwagę na typy po obu stronach `=`** — jeśli się różnią, zapytaj siebie, czy to zamierzone.
2. **Przy dzieleniu** — jeśli oczekujesz wyniku z częścią dziesiętną, upewnij się, że co najmniej jeden operand jest `float` lub `double`.
3. **Przy wpisywaniu do `byte`** — sprawdź, czy wartość mieści się w 0–255.
4. **Używaj jawnego rzutowania `(typ)`** gdy chcesz zmienić typ świadomie — kod staje się czytelniejszy i kompilator nie musi domyślać się intencji.
5. **Włącz ostrzeżenia kompilatora** — w Arduino IDE: *Plik → Preferencje → Szczegółowość kompilacji* lub użyj `-Wall` w PlatformIO.

## Ćwiczenia

**Ćwiczenie 1 — przewidywanie wyniku**
Co wypisze poniższy kod? Odpowiedz PRZED uruchomieniem, potem sprawdź.

```cpp
float a = 7.0 / 2;
int   b = 7.0 / 2;
int   c = 7 / 2;
float d = 7 / 2;

Serial.println(a);  // ?
Serial.println(b);  // ?
Serial.println(c);  // ?
Serial.println(d);  // ?
```

<details>
<summary>Odpowiedź</summary>

- `a` → `3.50` (7.0 to double → dzielenie zmiennoprzecinkowe → float)
- `b` → `3`    (7.0/2 = 3.5 → obcięcie do int)
- `c` → `3`    (dzielenie całkowite 7/2 = 3)
- `d` → `3.00` (dzielenie całkowite 7/2 = 3 → dopiero potem zamiana na float)

</details>

---

**Ćwiczenie 2 — przepełnienie byte**
Co wypisze `Serial.println((byte)260);`? Dlaczego?

<details>
<summary>Odpowiedź</summary>

Wypisze `4`. Typ `byte` to 8 bitów (0–255). Wartość 260 modulo 256 = 4.

</details>

---

**Ćwiczenie 3 — napraw kod**
Poniższy kod ma obliczać średnią z tablicy 5 odczytów i wypisywać ją z jednym miejscem po przecinku. Znajdź i napraw błąd związany z typami.

```cpp
int odczyty[5] = {10, 20, 30, 40, 50};
int suma = 0;

for (int i = 0; i < 5; i++) {
    suma += odczyty[i];
}

float srednia = suma / 5;
Serial.println(srednia, 1);   // powinno wypisać 30.0
```

<details>
<summary>Odpowiedź</summary>

`suma / 5` to dzielenie całkowite (oba operandy to `int`). Wynik `30` jest przypisywany do `float` — w tym przypadku akurat wychodzi dobrze, ale dla sumy np. `31` wynik byłby `6` zamiast `6.2`.

Poprawka: `float srednia = (float)suma / 5;` lub `float srednia = suma / 5.0;`

</details>
