# Monitor Portu Szeregowego — jak działa

Monitor to zwykły **terminal tekstowy** — wysyła i odbiera znaki, nie liczby. Wszystko co wpisujesz jest zamieniane na bajty według tabeli ASCII przed wysłaniem przez USB.

---

## Co się dzieje gdy wpisujesz `0`

```cpp
Ty piszesz:      0
Monitor wysyła:  bajt 48  (kod ASCII znaku '0')
Arduino odbiera: 48
```

Arduino nie wie że wpisałeś "zero" jako liczbę — dostaje bajt `48`, tak samo jak dostałoby literę innego znaku.

```cpp
Wpisujesz → Arduino odbiera (decimal)
'0'  →  48
'1'  →  49
'A'  →  65
'a'  →  97
' '  →  32   (spacja)
```

---

## Żeby Arduino dostało wartość `0`

Musiałbyś wysłać **surowy bajt** o wartości 0 — tego nie da się wpisać z klawiatury w Monitorze. Można to zrobić programowo z drugiego Arduino lub przez specjalne narzędzie (np. Putty w trybie hex).

Dlatego w kodzie porównujemy do znaku, nie liczby:

```cpp
ch == '0'   // ✅ czeka na naciśnięcie klawisza 0 → bajt 48
ch == 0     // ❌ czeka na bajt o wartości 0 — z klawiatury niemożliwe
```

---

## Wysyłanie liczb przez Serial — dwie drogi

**Droga 1 — tekst (to robi Monitor):**
```cpp
Arduino wysyła: Serial.println(255)
Na drucie leci: '2','5','5','\r','\n'  = bajty 50, 53, 53, 13, 10
Monitor wyświetla: 255  (jako tekst)
```

**Droga 2 — surowy bajt:**
```cpp
Arduino wysyła: Serial.write(255)
Na drucie leci: bajt 255
Monitor wyświetla: █  (znak o kodzie 255 — niedrukowany)
```

`Serial.print()` / `Serial.println()` → zawsze tekst ASCII, czytelny dla człowieka.
`Serial.write()` → surowe bajty, dla maszyn i protokołów binarnych.

---

## Praktyczna konsekwencja w kodzie

```cpp
byte ch = Serial.read();

// ❌ nigdy nie zadziała przy wpisywaniu z klawiatury
if (ch == 0) { digitalWrite(LED, LOW); }
if (ch == 1) { digitalWrite(LED, HIGH); }

// ✅ poprawnie — porównanie do znaków ASCII
if (ch == '0') { digitalWrite(LED, LOW); }
if (ch == '1') { digitalWrite(LED, HIGH); }
```
