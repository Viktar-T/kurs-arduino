# UART — komunikacja szeregowa

UART (Universal Asynchronous Receiver-Transmitter) to najprostszy **protokół** (interface) komunikacji szeregowej. Arduino używa go:
1. do komunikacji z komputerem przez USB.
	1. **Połączenie z PC:** Kiedy podłączasz Arduino kablem USB do komputera, specjalny konwerter na płytce zamienia sygnał USB na standard UART, co pozwala na korzystanie z **Monitora Portu Szeregowego**.
2. oraz z modułami (GPS, Bluetooth, HC-SR04).
	1. **Piny:** Do komunikacji UART służą piny cyfrowe Pin0 **(RX)** – odbiór danych oraz Pin1 **(TX)** – nadawanie danych.

# Przykład: komunikacja z komputerem przez USB

Piny **TX** i **RX** na płytce Arduino świecą (migają) gdy odbywa się komunikacja z PC przez USB.
![[../../../../../Pasted image 20260501120749.png|330]]

```cpp
// TX, RX na płytce Arduino — pokazuje kiedy odbywa się komunikacja z PC przez USB.
void setup() {
  Serial.begin(9600);
}

void loop() {
  // TX — Transmit: Arduino → PC
  // Co 1 sekundę wysyłamy sygnał z Arduino do PC. Dioda TX miga.
  Serial.print(digitalRead(10));
  delay(1000);

  // RX — Receive: PC → Arduino
  // Wpisz tekst w Monitorze Portu → Enter → dioda RX miga
  Serial.read();
}
```

**Obserwacja diod TX/RX:**
- **TX** — miga gdy Arduino **wysyła** dane do komputera (`Serial.print`, `Serial.println`)
- **RX** — miga gdy Arduino **odbiera** dane z komputera (wpisanie tekstu w Monitorze Portu → Enter)

# Teoria: UART
- UART To układ wewnątrz Twojego **Arduino UNO R3** (w mikrokontrolerze **ATmega328P**). Odpowiada on za zamianę danych z procesora na ciąg bitów wysyłanych jeden po drugim.
- Zasada działania UART opiera się na szeregowym wysłaniu ciągu bitów (od 5 do 9 bitów danych), które następnie składane są w informację. Pojedyncza ramka (w uproszczeniu bajt) danych jest nadawany w poniższej postaci:
	- ![[../../../../../Pasted image 20260501131037.png|354]]
- Transmisja rozpoczyna się od **bitu startu**, zaznaczonego na rysunku jako **BS**. Zawsze jest to bit będący logicznym zerem. Następnie, zależnie od konfiguracji, następuje po sobie **7, 8 lub 9 bitów danych** (tutaj zaznaczone jako B0-B7), które są wysyłaną informacją. **Bit stopu** (zaznaczony tutaj jako bit BK) to bit będący logiczną jedynką - mówi o końcu transmisji.

# Teoria: UART, USART, SPI, I2C - porównanie

W elektronice wyróżniamy dwa główne typy komunikacji szeregowej:
1. **Synchroniczna (np. SPI, I2C):** Urządzenia są połączone dodatkowym przewodem zegarowym (**CLK** lub **SCK**). Nadajnik wysyła impulsy zegara, które mówią odbiorcy dokładnie, w którym momencie ma odczytać kolejny bit danych.
2. **Asynchroniczna (UART):** Nie ma wspólnego przewodu zegarowego. Urządzenia „nie wiedzą” o sobie nawzajem, kiedy dokładnie nastąpi transmisja, dopóki się ona nie rozpocznie.

To, że transmisja jest **asynchroniczna**, oznacza, że synchronizacja odbywa się bez osobnej linii zegara, dzięki trzem mechanizmom:
- **Baud Rate (Prędkość transmisji):** Oba urządzenia muszą mieć z góry ustawioną tę samą prędkość (np. **9600 bodów**). Dzięki temu wiedzą, jak długo trwa przesyłanie jednego bitu.
- **Bit Startu (Start Bit):** Nadajnik wysyła specjalny sygnał na początku każdego bajtu, który informuje odbiorcę: „Uwaga, właśnie zaczynam wysyłać dane!”.
- **Bity Stopu (Stop Bits):** Sygnalizują koniec przesyłanego bajtu danych i pozwalają linii wrócić do stanu spoczynku.

# Teoria: Zasada działania
https://forbot.pl/blog/kurs-arduino-uart-komunikacja-z-komputerem-pc-zmienne-id3836

Dwa przewody: **TX** (nadawanie) i **RX** (odbieranie). Połączenie skrzyżowane — TX jednego urządzenia do RX drugiego.

Brak wspólnego zegara — obie strony muszą być ustawione na tę samą prędkość (**baud rate**).

## Użycie w Arduino

```cpp
Serial.begin(9600);       // inicjalizacja, prędkość 9600 baud

Serial.print("tekst");    // wyślij bez nowej linii
Serial.println("tekst");  // wyślij z nową linią (\r\n)
Serial.write(65);         // wyślij surowy bajt (65 = 'A')

if (Serial.available()) { // czy coś przyszło?
    char ch = Serial.read(); // odczytaj jeden bajt
}
```

## Ważne szczegóły

- Piny **0 (RX) i 1 (TX)** są zajęte przez UART — nie używaj ich jako zwykłych I/O gdy Serial jest aktywny
- `Serial.read()` zwraca `-1` gdy bufor pusty — zawsze sprawdzaj `Serial.available()` przed odczytem
- Monitor wysyła znaki **ASCII**, nie wartości liczbowe — `'0'` to bajt 48, nie 0
- Dla drugiego UART (np. do modułu GPS) użyj biblioteki `SoftwareSerial` na innych pinach

## Standardowe prędkości

9600, 19200, 38400, 57600, **115200** — obie strony muszą mieć identyczną wartość.

## 02 Sygnalizator otwarcia okna
Wyobraźmy sobie sytuację, w której **Arduino byłoby zamontowane w roli sygnalizatora** otwarcia okna, do którego ramy zamontowano specjalny przycisk/czujnik. Cały mechanizm działa w taki sposób, że gdy okno jest zamknięte przycisk zwierany jest do masy, w przeciwnym wypadku obwód jest przerwany.
Wyposażmy Arduino w przycisk (imitujący sensor w ramie okna) oraz dwie diody (zieloną i czerwoną).
Gdy okno jest zamknięte (przycisk wciśnięty) świeci się zielona dioda. Gdy przerwiemy obwód (przestaniemy wciskać przycisk) powinna włączyć się czerwona dioda, a w terminalu powinniśmy odczytać komunikat _"Uwaga! Alarm! Okno nie jest zamknięte!"_.
![[../../../../../Pasted image 20260501132250.png|340]]
```cpp
const byte pinG = 8;
const byte pinR = 10;
const byte pinBTN = 12;

  

void setup() {

  pinMode(pinG, OUTPUT);
  pinMode(pinR, OUTPUT);
  pinMode(pinBTN, INPUT_PULLUP);
  
  digitalWrite(pinG, LOW);
  digitalWrite(pinR, LOW);

  Serial.begin(9600);

}

  

void loop() {

  byte btnStatus = digitalRead(pinBTN);

  if (btnStatus == LOW) {
    digitalWrite(pinG, HIGH);
    digitalWrite(pinR, LOW);
    Serial.println("Okno jest zamkniente");
  } else if (btnStatus == HIGH) {
    digitalWrite(pinG, LOW);
    digitalWrite(pinR, HIGH);
    Serial.println("Uwaga! Alarm! Okno nie jest zamkniete!");
  }
  delay(1000);

}
```
