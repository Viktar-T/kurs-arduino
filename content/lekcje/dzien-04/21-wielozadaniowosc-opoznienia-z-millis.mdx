Funkcja `delay()` to jedna z pierwszych, których uczymy się w Arduino. Jest prosta i wygodna, ale jej działanie może generować poważne kłopoty w bardziej rozbudowanych projektach. W tej lekcji poznasz **funkcję `millis()`**, która pozwala odmierzać czas bez blokowania programu, i nauczysz się pisać kod, który robi kilka rzeczy jednocześnie.

<Callout type="note">
Lekcja odpowiada rozdziałowi **#9** kursu *Kurs Arduino, poziom II* na portalu Forbot.pl. Zakłada, że znasz już podstawy obsługi wejść i wyjść cyfrowych, a także potrafisz korzystać z monitora portu szeregowego.
</Callout>

## 1. Problem z delay() — dlaczego blokuje program?

Miganie diodą to klasyczny "Hello, World!" świata Arduino. Najprostszy szkic wygląda tak:

<Code lang="cpp" file="blink_delay.ino">
```cpp
#define LED1pin 3

void setup() {
  pinMode(LED1pin, OUTPUT);
}

void loop() {
  digitalWrite(LED1pin, HIGH);
  delay(1000);
  digitalWrite(LED1pin, LOW);
  delay(1000);
}
```
</Code>

Pętla `loop()` jest krótka i działa bez zarzutu. Animacja poniżej pokazuje, jak wygląda jej działanie w czasie:

<Photo
  src="/img/lekcje/21.01-petla-loop-delay-animacja.gif"
  caption="Zawartość pętli loop() migającej jedną diodą co 1 sekundę"
  alt="Animacja pętli loop z delay(1000)"
/>

Wiele osób wpada na pomysł, żeby w ten sam sposób migać **dwiema diodami z różną częstotliwością**:

<Code lang="cpp" file="blink2_delay_problem.ino">
```cpp
#define LED1pin 3
#define LED2pin 4

void setup() {
  pinMode(LED1pin, OUTPUT);
  pinMode(LED2pin, OUTPUT);
}

void loop() {
  digitalWrite(LED1pin, HIGH);
  delay(1000);
  digitalWrite(LED1pin, LOW);
  delay(1000);

  digitalWrite(LED2pin, HIGH);
  delay(500);
  digitalWrite(LED2pin, LOW);
  delay(500);
}
```
</Code>

Działanie tego kodu **odbiega od oczekiwań**. Arduino wykonuje instrukcje z `loop()` linijka po linijce. Funkcja `delay()` całkowicie zatrzymuje działanie programu — żadna inna instrukcja nie jest w tym czasie wykonywana.

<Photo
  src="/img/lekcje/21.02-dwie-diody-delay-problem.gif"
  caption="Pozorne rownolegle miganie dwiema diodami — w rzeczywistosci diody dzialaja naprzemiennie"
  alt="Animacja pokazujaca problem z delay() przy dwoch diodach"
/>

### Kiedy można korzystać z delay()?

Funkcja `delay()` jest niezwykle prosta i wygodna. W prostych przykładach, gdzie program ma tylko jedno zadanie, nie stanowi problemu. Przy większych projektach jest jednak **problematyczna**, bo:

- blokuje odczyt przycisków i czujników,
- uniemożliwia jednoczesne sterowanie kilkoma elementami,
- sprawia, że układ nie reaguje na zdarzenia w czasie rzeczywistym.

<Callout type="warning">
Każde użycie `delay()` **zamraża cały program** na podaną liczbę milisekund. Pamiętaj o tym projektując bardziej złożone układy.
</Callout>

## 2. Co zamiast delay()?

Istnieje wiele bibliotek pozwalających na nieblokujące opóźnienia. Zanim jednak sięgniesz po gotowe rozwiązanie, warto **przestawić sposób myślenia** i nauczyć się pisać programy inaczej — zaczynając od podstaw, bez gotowych bibliotek.

Kluczowa zmiana w podejściu: zamiast "zatrzymać program na sekundę", będziemy **sprawdzać, czy minęła sekunda** przy każdym obiegu pętli.

## 3. Stoper wbudowany w Arduino — millis()

W Arduino wbudowany jest dokładny stoper: **funkcja `millis()`**. Jej działanie najlepiej przyrównać do stopera uruchamianego w momencie podłączenia płytki do zasilania.

<Photo
  src="/img/lekcje/21.03-stoper-millis.jpg"
  caption="millis() dziala jak wbudowany stoper odmierzajacy czas od startu Arduino"
  alt="Zdjecie stopera ilustrujace dzialanie millis()"
/>

Funkcja `millis()`:
- **nie przyjmuje żadnego argumentu**,
- **zwraca liczbę milisekund** od uruchomienia Arduino jako `unsigned long`,
- działa sprzętowo (przez timery) — nawet `delay()` jej nie zatrzyma,
- **przepełni się po ok. 50 dniach** pracy i zacznie liczyć od zera (to normalne zachowanie).

### Jak korzystać z millis()?

Zwracana wartość rośnie bardzo szybko — musi być przechowywana w zmiennej **`unsigned long`** (32-bitowa liczba bez znaku, zakres 0–4 294 967 295):

```cpp
unsigned long aktualnyCzas = millis();
```

Sprawdzenie działania stopera przez wysyłanie czasu do komputera przez UART:

<Code lang="cpp" file="millis_test.ino">
```cpp
unsigned long aktualnyCzas = 0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  aktualnyCzas = millis();
  Serial.println(aktualnyCzas);
  delay(1000);
}
```
</Code>

<Photo
  src="/img/lekcje/21.04-millis-wysylanie-czasu-uart.gif"
  caption="Czas w milisekundach wypisywany co ok. sekunde w monitorze portu szeregowego"
  alt="Terminal pokazujacy rosnace wartosci millis()"
/>

<Callout type="note">
Liczenie czasu tą metodą nie jest idealnie dokładne — mogą pojawiać się odchylenia rzędu plus/minus 1 ms. Do większości zastosowań w kursie jest to całkowicie wystarczające.
</Callout>

## 4. Wzorzec nieblokującego opóźnienia

Teraz znamy stoper. Jak go wykorzystać do odmierzania czasu bez blokowania programu?

**Algorytm odmierzania 1 sekundy:**

1. Pobierz aktualny czas z `millis()` i go zapamiętaj.
2. Przy każdym obiegu pętli ponownie pobierz aktualny czas.
3. Jeśli różnica między aktualnym a zapamiętanym czasem jest większa lub równa 1000 ms, wykonaj zadanie i zaktualizuj zapamiętany czas.

Program **cały czas biega w kółko** — nigdzie się nie zatrzymuje.

<Code lang="cpp" file="millis_sekunda.ino">
```cpp
unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzas = 0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  aktualnyCzas = millis();

  if (aktualnyCzas - zapamietanyCzas >= 1000UL) {
    zapamietanyCzas = aktualnyCzas;
    Serial.println(aktualnyCzas);
  }
}
```
</Code>

<Callout type="note">
Sufiks **`UL`** (Unsigned Long) przy liczbie 1000 informuje kompilator, że działanie powinno być wykonane na liczbach bez znaku — ważne dla poprawności obliczeń, szczególnie przy przepełnieniu licznika.

Używamy warunku `>= 1000` zamiast `== 1000`, żeby program nie "zatrzasnął się" w przypadku, gdy obieg pętli trwa dłużej niż 1 ms.
</Callout>

## 5. Miganie diody bez delay()

Teraz wykorzystamy wzorzec z poprzedniej sekcji do migania diodą. Musimy zapamiętać **aktualny stan diody** (świeci / nie świeci) i w momencie upłynięcia czasu — odwrócić go.

Podłącz diodę LED do **pinu 3** (przez rezystor 220 Ω do GND).

<Code lang="cpp" file="blink_millis.ino">
```cpp
#define LED1 3
int stanLED1 = LOW;

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;

void setup() {
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
}

void loop() {
  aktualnyCzas = millis();

  if (aktualnyCzas - zapamietanyCzasLED1 >= 1000UL) {
    zapamietanyCzasLED1 = aktualnyCzas;
    stanLED1 = !stanLED1;
    digitalWrite(LED1, stanLED1);
  }
}
```
</Code>

<Photo
  src="/img/lekcje/21.06-millis-miganie-diody.gif"
  caption="Miganie diody LED przy uzyciu millis() — program nie jest blokowany"
  alt="Animacja migania diody z millis()"
/>

<Callout type="tip">
Operator `!` (negacja logiczna) użyty na wartości `LOW` (0) daje `HIGH` (1) i odwrotnie. To elegancki sposób na przełączanie stanu diody bez instrukcji `if/else`.
</Callout>

## 6. Wielozadaniowość — niezależne miganie dwóch diod

Pora rozbudować przykład i migać **dwiema diodami niezależnie** — każdą z własną częstotliwością. Pętla `loop()` pozostaje jedna. Wszystkie zadania wykonywane są linijka po linijce, ale dzięki wzorcowi z `millis()` wyglądają jak równoległe.

<Photo
  src="/img/lekcje/21.07-dwie-czestotliwosci-animacja.gif"
  caption="Dwa rownolegle zadania w jednej petli loop() — kazda dioda ma wlasny interwal"
  alt="Animacja dwoch zadan w loop()"
/>

Potrzebujemy osobnych zmiennych dla każdej diody: zapamiętany czas i aktualny stan. Podłącz **drugą diodę do pinu 4**.

<Code lang="cpp" file="blink2_millis.ino">
```cpp
#define LED1 3
#define LED2 4

int stanLED1 = LOW;
int stanLED2 = LOW;

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;
unsigned long zapamietanyCzasLED2 = 0;

void setup() {
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
  pinMode(LED2, OUTPUT);
}

void loop() {
  aktualnyCzas = millis();

  if (aktualnyCzas - zapamietanyCzasLED1 >= 1000UL) {
    zapamietanyCzasLED1 = aktualnyCzas;
    stanLED1 = !stanLED1;
    digitalWrite(LED1, stanLED1);
  }

  if (aktualnyCzas - zapamietanyCzasLED2 >= 500UL) {
    zapamietanyCzasLED2 = aktualnyCzas;
    stanLED2 = !stanLED2;
    digitalWrite(LED2, stanLED2);
  }
}
```
</Code>

  src="/img/lekcje/21.08-millis-dwie-diody-niezalezne.jpg"

Dla większej widoczności różnicy można zmienić interwały i przenieść je do osobnych zmiennych. Zmień drugą diodę na interwał **200 ms**:

<Code lang="cpp" file="blink2_millis_zmienne.ino">
```cpp
#define LED1 3
#define LED2 4

int stanLED1 = LOW;
int stanLED2 = LOW;

unsigned long miganieLED1 = 1000;
unsigned long miganieLED2 = 200;

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;
unsigned long zapamietanyCzasLED2 = 0;

void setup() {
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
  pinMode(LED2, OUTPUT);
}

void loop() {
  aktualnyCzas = millis();

  if (aktualnyCzas - zapamietanyCzasLED1 >= miganieLED1) {
    zapamietanyCzasLED1 = aktualnyCzas;
    stanLED1 = !stanLED1;
    digitalWrite(LED1, stanLED1);
  }

  if (aktualnyCzas - zapamietanyCzasLED2 >= miganieLED2) {
    zapamietanyCzasLED2 = aktualnyCzas;
    stanLED2 = !stanLED2;
    digitalWrite(LED2, stanLED2);
  }
}
```
</Code>

## 7. Dodanie przycisku — natychmiastowa reakcja na wejście

Gdybyśmy korzystali z `delay()`, każde jego wywołanie blokowałoby możliwość natychmiastowego sprawdzania stanu wejść. Dzięki wzorcowi z `millis()` nie ma tego problemu — możemy dodać obsługę przycisku, który działa natychmiast.

Niech wciśnięcie przycisku (pin 2, INPUT_PULLUP) sprawia, że **LED1 miga szybciej** (co 100 ms zamiast co 2000 ms):

<Code lang="cpp" file="blink2_millis_przycisk.ino">
```cpp
#define LED1      3
#define LED2      4
#define PRZYCISK  2

int stanLED1 = LOW;
int stanLED2 = LOW;

unsigned long miganieLED1 = 1000;
unsigned long miganieLED2 = 200;

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;
unsigned long zapamietanyCzasLED2 = 0;

void setup() {
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
  pinMode(LED2, OUTPUT);
  pinMode(PRZYCISK, INPUT_PULLUP);
}

void loop() {
  aktualnyCzas = millis();

  if (digitalRead(PRZYCISK) == LOW) {
    miganieLED1 = 100;
  } else {
    miganieLED1 = 2000;
  }

  if (aktualnyCzas - zapamietanyCzasLED1 >= miganieLED1) {
    zapamietanyCzasLED1 = aktualnyCzas;
    stanLED1 = !stanLED1;
    digitalWrite(LED1, stanLED1);
  }

  if (aktualnyCzas - zapamietanyCzasLED2 >= miganieLED2) {
    zapamietanyCzasLED2 = aktualnyCzas;
    stanLED2 = !stanLED2;
    digitalWrite(LED2, stanLED2);
  }
}
```
</Code>

### Program z millis()

Przed poznaniem `millis()` włączenie światła na 180 s realizowalibyśmy przez `delay(180000)`. Cały układ byłby zamrożony i nie reagowałby ani na kontaktron, ani na PIR.

<Code lang="cpp" file="schody_millis.ino">
```cpp
#define OSWIETLENIE  4
#define KONTAKTRON   3
#define PIR          5

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasOswietlenie = 0;

void setup() {
  Serial.begin(9600);
  pinMode(OSWIETLENIE, OUTPUT);
  pinMode(KONTAKTRON, INPUT_PULLUP);
  pinMode(PIR, INPUT);
}

void loop() {
  aktualnyCzas = millis();

  if (digitalRead(KONTAKTRON) == HIGH) {
    digitalWrite(OSWIETLENIE, LOW);
  } else if (digitalRead(PIR) == HIGH) {
    zapamietanyCzasOswietlenie = aktualnyCzas;
    digitalWrite(OSWIETLENIE, HIGH);
  }

  if (aktualnyCzas - zapamietanyCzasOswietlenie >= 180000UL) {
    digitalWrite(OSWIETLENIE, LOW);
  }
}
```
</Code>

<Callout type="note">
Program można rozbudować o **fotorezystor** — dzięki niemu oświetlenie włączałoby się tylko w ciemności. To ćwiczenie do samodzielnego wykonania.
</Callout>

**Kluczowe pojęcia z tej lekcji:**

- `millis()` zwraca liczbę milisekund od uruchomienia Arduino i działa jak sprzętowy stoper.
- Wzorzec `if (millis() - zapamietanyCzas >= INTERWAL)` zastępuje `delay()` bez blokowania programu.
- Każde niezależne zadanie wymaga własnej zmiennej `zapamietanyCzas` i zmiennej stanu.
- Typ zmiennej do przechowywania czasu to zawsze **`unsigned long`**; literały milisekund zapisujemy z sufiksem `UL`.
