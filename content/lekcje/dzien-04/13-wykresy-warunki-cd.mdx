## 1. Rysowanie wykresów z Arduino

<Expandable title="Jak często można odświeżać wykres?" heading="####">

Serial Plotter odczytuje dane tak szybko, jak Arduino je wysyła. Przy `delay(200)` dostajesz 5 próbek na sekundę — przy `delay(50)` już 20, obraz jest wyraźnie płynniejszy.

Baud rate (`Serial.begin(9600)`) przy prostych liczbach nie jest wąskim gardłem. Jednak przy bardzo krótkich opóźnieniach (< 10 ms) warto zwiększyć go do `115200`, żeby dane nie zalegały w buforze portu i wykres odzwierciedlał aktualny stan układu:

```cpp
void setup() {
  Serial.begin(115200); // szybsza transmisja = aktualniejszy wykres
}
```

</Expandable>

## 2. Wykres odległości od przeszkody

Teraz wyślemy dane z czujnika HC-SR04 do Plottera. Podłącz czujnik tak samo jak w [lekcji 12, rozdziale „Miernik odległości”](../dzien-03/12.02-czujnik-hc-sr04#2-miernik-odleglosci) (`trigPin = 12`, `echoPin = 11`):

<Code lang="cpp" file="hc-sr04-wykres.ino">
```cpp
const byte trigPin = 12;
const byte echoPin = 11;

void setup() {
  Serial.begin(9600);
  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);
}

void loop() {
  long czas, dystans;

  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  czas = pulseIn(echoPin, HIGH);
  dystans = czas / 58;

  Serial.println(dystans);
  delay(100);
}
```
</Code>

Gdy nic nie stoi przed czujnikiem, `pulseIn()` czeka na echo zbyt długo i zwraca `0` albo bardzo dużą wartość. Widać to na wykresie jako piki:

<Photo
  file="13.05-czujnik-wykres-blad.png"
  caption="Wykres z błędną wartością 2000 cm — czujnik nie wykrył echa w ustalonym czasie."
  alt="Serial Plotter: pik 2000 cm w danych z czujnika HC-SR04"
  width={500}
  height={250}
/>

Naprawmy to: ograniczmy maksymalną wartość do zakresu podawanego przez producenta (400 cm):

<Code lang="cpp" file="hc-sr04-wykres-poprawiony.ino">
```cpp
const byte trigPin = 12;
const byte echoPin = 11;

void setup() {
  Serial.begin(9600);
  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);
}

void loop() {
  long czas, dystans;

  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  czas = pulseIn(echoPin, HIGH);
  dystans = czas / 58;

  if (dystans > 400) {
    dystans = 400;
  }

  Serial.println(dystans);
  delay(100);
}
```
</Code>

<Expandable title="pulseIn() — timeout i tryb nieblokujący" heading="####">

`pulseIn(pin, HIGH)` czeka, aż sygnał przejdzie z LOW na HIGH, po czym mierzy czas trwania impulsu. Domyślnie czeka maksymalnie **1 sekundę** — gdy nic nie stoi przed czujnikiem, program „zamarza" na tę chwilę przy każdym pomiarze.

Możesz to naprawić, przekazując trzeci argument — limit czasu w mikrosekundach:

```cpp
czas = pulseIn(echoPin, HIGH, 25000); // max 25 ms → odpowiada ~4 m
```

Fala dźwiękowa przy 400 cm przebywa trasę tam i z powrotem w ok. 23 ms, więc 25 000 µs w zupełności wystarczy. Gdy nic nie wykryto, funkcja zwraca `0` natychmiast, zamiast czekać pełną sekundę — pętla `loop()` pracuje wyraźnie szybciej.

</Expandable>

## 4. Łączenie instrukcji warunkowych

Operator `||` to **lub** — warunek jest spełniony, gdy przynajmniej jedna część jest prawdziwa. Operator `&&` to **i** — obie muszą być prawdziwe.

<Schematic
  src="/img/lekcje/13.16-schemat-przyciski-diody.png"
  caption="Schemat układu: dwa przyciski (piny 9 i 10) i dwie diody LED (Light Emitting Diode, dioda elektroluminescencyjna) (piny 7 i 8)."
  alt="Schemat elektryczny z dwoma przyciskami i dwiema diodami LED podłączonymi do Arduino"
  width={600}
  height={400}
/>

Podłącz dwa przyciski do pinów `9` i `10` (z `INPUT_PULLUP`), a dwie diody do pinów `7` i `8`.

### Operator OR — dioda zielona

Dioda zielona (pin `8`) świeci, gdy **którykolwiek** przycisk jest wciśnięty:

<Code lang="cpp" file="warunki-or.ino">
```cpp
const byte PIN_BTN1  = 10;
const byte PIN_BTN2  = 9;
const byte PIN_LED_G = 8;
const byte PIN_LED_R = 7;

void setup() {
  pinMode(PIN_BTN1,  INPUT_PULLUP);
  pinMode(PIN_BTN2,  INPUT_PULLUP);
  pinMode(PIN_LED_G, OUTPUT);
  pinMode(PIN_LED_R, OUTPUT);
  digitalWrite(PIN_LED_G, LOW);
  digitalWrite(PIN_LED_R, LOW);
}

void loop() {
  if (digitalRead(PIN_BTN2) == LOW || digitalRead(PIN_BTN1) == LOW) {
    digitalWrite(PIN_LED_G, HIGH);
  } else {
    digitalWrite(PIN_LED_G, LOW);
  }
}
```
</Code>

### Operator AND — dioda czerwona

Dioda czerwona (pin `7`) świeci tylko wtedy, gdy **oba** przyciski są wciśnięte jednocześnie:

<Code lang="cpp" file="warunki-and-or.ino">
```cpp
const byte PIN_BTN1  = 10;
const byte PIN_BTN2  = 9;
const byte PIN_LED_G = 8;
const byte PIN_LED_R = 7;

void setup() {
  pinMode(PIN_BTN1,  INPUT_PULLUP);
  pinMode(PIN_BTN2,  INPUT_PULLUP);
  pinMode(PIN_LED_G, OUTPUT);
  pinMode(PIN_LED_R, OUTPUT);
  digitalWrite(PIN_LED_G, LOW);
  digitalWrite(PIN_LED_R, LOW);
}

void loop() {
  if (digitalRead(PIN_BTN2) == LOW || digitalRead(PIN_BTN1) == LOW) {
    digitalWrite(PIN_LED_G, HIGH);
  } else {
    digitalWrite(PIN_LED_G, LOW);
  }

  if (digitalRead(PIN_BTN2) == LOW && digitalRead(PIN_BTN1) == LOW) {
    digitalWrite(PIN_LED_R, HIGH);
  } else {
    digitalWrite(PIN_LED_R, LOW);
  }
}
```
</Code>

<Expandable title="Głębiej: ocena leniwa (short-circuit) i jej praktyczne pułapki" heading="####">
C++ stosuje tzw. **ocenę leniwą** (ang. *short-circuit evaluation*) dla operatorów `&&` i `||`. To znaczy, że kompilator przerywa sprawdzanie warunku, gdy wynik jest już znany:

- `A && B` — jeśli `A` jest fałszywe, `B` **nigdy nie zostanie obliczone** (cały warunek na pewno fałszywy).
- `A || B` — jeśli `A` jest prawdziwe, `B` **nigdy nie zostanie obliczone** (cały warunek na pewno prawdziwy).

**Praktyczna korzyść:** możesz bezpiecznie sprawdzić warunek wstępny przed potencjalnie niebezpiecznym wyrażeniem:

```cpp
if (czujnikPodlaczony && analogRead(A0) > 500) {
  // Jeśli czujnik nie jest podłączony, analogRead się nie wykona
}
```

**Pułapka — efekty uboczne w warunkach:** jeśli w warunku wywołasz funkcję, która **coś robi** (zwiększa licznik, zapisuje do EEPROM, miga diodą), short-circuit może spowodować, że funkcja nie zostanie wywołana w ogóle.

```cpp
if (false && zwiekszLicznik()) {  // zwiekszLicznik() NIGDY się nie wykona
  ...
}
```

Dlatego dobra praktyka: w warunkach `if` używaj tylko **funkcji bez efektów ubocznych** (czystych) — np. odczyt pinu, porównanie zmiennych. Funkcje, które coś zmieniają w systemie, wywołuj w osobnych liniach przed `if`.
</Expandable>

<Expandable title="Operator ! i prawa De Morgana" heading="####">

Operator `!` odwraca wartość logiczną: `!true` daje `false` i odwrotnie. Przydaje się, gdy chcesz sprawdzić, że coś **nie** jest prawdziwe:

```cpp
if (!digitalRead(8)) { ... }  // równoważne: digitalRead(8) == LOW
```

**Prawo De Morgana** pozwala przekształcać złożone warunki:
- `!(A && B)` jest równoważne `!A || !B`
- `!(A || B)` jest równoważne `!A && !B`

XOR z Zadania 4 możesz więc zapisać na dwa równoważne sposoby:

```cpp
(A || B) && !(A && B)    // tradycyjny zapis
(A || B) && (!A || !B)   // po rozwinięciu De Morgana
```

Obie wersje dają identyczny wynik — wybierz tę, która jest dla ciebie czytelniejsza.

</Expandable>

## 5. Warunki w praktyce — alarm z czujnikiem i przyciskiem

Połączmy to wszystko. Program włącza buzzer, gdy obiekt jest w odległości 20–40 cm **lub** gdy przycisk jest wciśnięty — alarm działa zarówno automatycznie, jak i ręcznie:

<Photo
  file="13.17-montaz-czujnik-buzzer.jpg"
  caption="Układ z czujnikiem HC-SR04, przyciskiem i buzzerem."
  alt="Fotografia zmontowanego układu: Arduino, HC-SR04, przycisk i buzzer"
  width={650}
  height={433}
/>

<Expandable title="Przykład kodu" heading="####">

<Code lang="cpp" file="alarm-czujnik-przycisk.ino">
```cpp
const byte trigPin   = 12;
const byte echoPin   = 9;
const byte PIN_BTN   = 10;
const byte PIN_BUZZER = 11;

void setup() {
  pinMode(trigPin,    OUTPUT);
  pinMode(echoPin,    INPUT);
  pinMode(PIN_BTN,    INPUT_PULLUP);
  pinMode(PIN_BUZZER, OUTPUT);
  digitalWrite(PIN_BUZZER, LOW);
}

void loop() {
  long czas, dystans;

  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  czas = pulseIn(echoPin, HIGH);
  dystans = czas / 58;

  if ((dystans > 20 && dystans < 40) || digitalRead(PIN_BTN) == LOW) {
    digitalWrite(PIN_BUZZER, HIGH);
  } else {
    digitalWrite(PIN_BUZZER, LOW);
  }
}
```
</Code>

</Expandable>

<Callout type="tip" title="Czytaj warunek od prawej do lewej">
`(dystans > 20 && dystans < 40) || digitalRead(10) == LOW` — najpierw sprawdzamy, czy dystans mieści się w oknie 20–40 cm, a potem, czy przycisk jest wciśnięty. Wystarczy jeden z tych faktów, żeby alarm zadziałał.
</Callout>

<Expandable title="Histereza — jak unikać drgania alarmu na granicy" heading="####">

Gdy obiekt stoi dokładnie 20 cm od czujnika, drobny szum pomiaru sprawia, że odczyt skacze: 19, 21, 20, 19, 21 cm. Alarm włącza i wyłącza się kilka razy na sekundę — to niepożądane zjawisko zwane *chattering*.

Rozwiązanie to **histereza**: dwie różne granice — osobna dla włączania, osobna dla wyłączania:

```cpp
bool alarm = false;

void loop() {
  long dystans = zmierzOdleglosc();

  if (!alarm && dystans < 25) {
    alarm = true;   // włącz, gdy obiekt bliżej niż 25 cm
  }
  if (alarm && dystans > 30) {
    alarm = false;  // wyłącz dopiero gdy dalej niż 30 cm
  }

  digitalWrite(11, alarm ? HIGH : LOW);
}
```

Masz teraz 5 cm „strefy buforowej" — alarm nie będzie drżał przy granicy progu.

</Expandable>

<MiniProject title="System parkowania" estimate="20 min">

Zbuduj uproszczony system pomocy parkowania:
- Odległość > 40 cm: cisza, dioda zielona.
- Odległość 20–40 cm: dioda żółta, buzzer „pika" wolno (1 sek. przerwy).
- Odległość < 20 cm: dioda czerwona, buzzer „pika" szybko (200 ms przerwy).

Skorzystaj z funkcji `zmierzOdleglosc()` z poprzedniej lekcji i warunków `if-else if-else`.

## Podsumowanie

Serial Plotter przekształca liczby z `Serial.println()` w wykres — wystarczy zamienić tekst na gołe cyfry. Kilka serii jednocześnie oddzielasz tabulatorami. Operatory `&&` i `||` pozwalają łączyć wiele warunków w jednej decyzji: czujnik i przycisk mogą razem decydować, czy alarm ma zabrzmieć. To solidna baza do własnych projektów — każdy z tych elementów możesz teraz łączyć swobodnie.
