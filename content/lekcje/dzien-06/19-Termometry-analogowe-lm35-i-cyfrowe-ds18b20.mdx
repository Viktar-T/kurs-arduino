W tej lekcji porównamy dwa podejścia do pomiaru temperatury: **analogowe** (czujnik LM35) i **cyfrowe** (czujnik DS18B20). Poznamy zasadę działania obu sensorów, podłączymy je do Arduino i napiszemy programy odczytujące temperaturę — w tym wersję z zapamiętywaniem wartości minimalnej i maksymalnej. Na koniec połączymy DS18B20 z linijką diod WS2812, aby zbudować kolorowy termometr pokojowy.

## 1. Czujnik analogowy a czujnik cyfrowy

Na rynku dostępna jest ogromna liczba czujników. Można je podzielić na dwie główne grupy:

**Czujniki analogowe** zamieniają mierzoną wielkość (np. temperaturę) na wielkość elektryczną proporcjonalną do odczytanej wartości. Wraz ze wzrostem temperatury na wyjściu czujnika rośnie napięcie lub maleje rezystancja.

**Czujniki cyfrowe** wysyłają informację w postaci ciągu bitów. Do odczytania tych danych potrzebny jest mikrokontroler — np. Arduino.

## 2. Termometr analogowy: LM35

LM35 to popularny czujnik zamknięty w obudowie TO-92 — takiej samej jak wiele tranzystorów. Skrajne wyprowadzenia to zasilanie, a środkowy pin to wyjście pomiarowe.

  width={500}

Najważniejsze parametry LM35:

- skalibrowany dla skali Celsjusza: **10 mV/°C** (czujnik liniowy),
- zakres pomiaru: **0 do 100 °C**,
- napięcie zasilania: **4 do 30 V**.

Sensor jest **liniowy** — wzrost napięcia wyjściowego o 10 mV oznacza zawsze dodatkowy 1 °C. Przy 25 °C na wyjściu czujnika mierzymy 250 mV.

## 4. Odczytanie temperatury — LM35

Program musi: odczytać wartość ADC z pinu A5, przeliczyć ją na napięcie (mnożąc przez 5 V / 1024), a następnie pomnożyć przez 100 (bo 10 mV = 1 °C).

<Code lang="cpp" file="lm35-podstawowy.ino">
```cpp
const byte LM35 = A5;

void setup() {
  Serial.begin(9600);
}

void loop() {
  // Przeliczenie odczytu ADC na temperaturę
  float temperatura = ((analogRead(LM35) * 5.0) / 1024.0) * 100;

  Serial.print("Aktualna temperatura: ");
  Serial.print(temperatura);
  Serial.println("*C");

  delay(200);
}
```
</Code>

<Expandable title="Głębiej: skąd bierze się rozdzielczość pomiaru LM35?" heading="####">

Arduino UNO mierzy napięcie wejściowe przetwornikiem ADC o rozdzielczości 10 bitów, czyli zwraca wartości od `0` do `1023`. Przy domyślnym odniesieniu `5 V` jeden krok ADC odpowiada około `4,88 mV`.

LM35 daje `10 mV` na każdy 1 °C, więc jeden krok ADC to mniej więcej `0,49 °C`. Oznacza to, że nawet przy idealnym czujniku odczyt będzie przeskakiwał skokami około pół stopnia, jeśli używamy domyślnego zakresu 0–5 V.

Precyzję można poprawić przez stabilniejsze napięcie odniesienia albo uśrednianie wielu pomiarów. Uśrednianie nie zwiększa prawdziwej dokładności czujnika, ale zmniejsza przypadkowe wahania odczytu w Monitorze portu szeregowego.

</Expandable>

</Callout>

## 5. Termometr z funkcją MAX/MIN — LM35

Rozbudujemy program o zapamiętywanie najwyższej i najniższej zmierzonej temperatury.

### Śledzenie maksimum

Deklarujemy zmienną **poza** `loop()` — inaczej zeruje się przy każdym obiegu pętli:

```cpp
float tempMAX = 0; // Aktualna temperatura maksymalna
```

W każdej iteracji sprawdzamy, czy bieżąca temperatura jest wyższa od zapamiętanej:

<Code lang="cpp" file="lm35-max.ino">
```cpp
const byte LM35 = A5;

float tempMAX = 0; // Aktualna temperatura maksymalna

void setup() {
  Serial.begin(9600);
}

void loop() {
  float temperatura = ((analogRead(LM35) * 5.0) / 1024.0) * 100;

  if (temperatura > tempMAX) { // Jeśli wyższa od dotychczasowego maksimum
    tempMAX = temperatura;     // zaktualizuj wartość
  }

  Serial.print("Max: ");
  Serial.print(tempMAX);
  Serial.println("*C");

  delay(200);
}
```
</Code>

### Śledzenie minimum i maksimum

Pułapka przy śledzeniu minimum: jeśli inicjujemy zmienną wartością `0`, nigdy nie zarejestrujemy niższej temperatury (czujnik nie mierzy ujemnych). Dlatego inicjujemy `tempMIN` wartością maksymalną zakresu — `150`.

<Code lang="cpp" file="lm35-min-max.ino">
```cpp
const byte LM35 = A5;

float tempMAX = 0;   // Aktualna temperatura maksymalna
float tempMIN = 150; // Inicjujemy górną granicą zakresu!

void setup() {
  Serial.begin(9600);
}

void loop() {
  float temperatura = ((analogRead(LM35) * 5.0) / 1024.0) * 100;

  if (temperatura > tempMAX) {
    tempMAX = temperatura;
    Serial.print("Nowa wartosc max: ");
    Serial.print(tempMAX);
    Serial.println("*C");
  }

  if (temperatura < tempMIN) {
    tempMIN = temperatura;
    Serial.print("Nowa wartosc min: ");
    Serial.print(tempMIN);
    Serial.println("*C");
  }

  delay(200);
}
```
</Code>

  file="19.07-lm35-min-max-temperatura.gif"

  alt="Animacja monitora portu szeregowego pokazująca śledzenie minimalnej i maksymalnej temperatury"
  width={700}

<Expandable title="Dlaczego inicjalizujemy tempMIN = 150?" heading="###">
Jeśli ustawimy `tempMIN = 0`, a czujnik mierzy +22 °C, warunek `temperatura < tempMIN` nigdy nie będzie spełniony (22 nie jest mniejsze od 0). W efekcie minimum nigdy się nie zaktualizuje. Inicjując zmienną wartością wyższą niż jakakolwiek możliwa temperatura (150), gwarantujemy, że pierwszy prawdziwy odczyt od razu stanie się minimum. W kolejnej sekcji zobaczymy elegantsze rozwiązanie tego problemu (użycie pierwszego odczytu z `setup()`).
</Expandable>

<Task title="Zadanie 7.1 — dwa czujniki LM35" estimate="15 min">

## 8. Odczytanie temperatury — DS18B20

Komunikacja z DS18B20 przebiega przez bibliotekę `DallasTemperature`. Zaczniemy od odczytu krokowego, a potem pokażemy pełny program.

**Krok 1 — dołącz biblioteki:**

```cpp
#include <OneWire.h>
#include <DallasTemperature.h>
```

**Krok 2 — zadeklaruj podłączenie:**

```cpp
const byte PIN_DS18B20 = A5;
OneWire oneWire(PIN_DS18B20);        // Linia 1-Wire na pinie A5
DallasTemperature sensors(&oneWire); // Przekaż obiekt oneWire do biblioteki
```

**Krok 3 — inicjalizacja i odczyt:**

```cpp
void setup() {
  Serial.begin(9600);
  sensors.begin(); // Inicjalizacja czujników
}

void loop() {
  sensors.requestTemperatures(); // Pobierz temperatury ze wszystkich czujników
  Serial.print("Aktualna temperatura: ");
  Serial.println(sensors.getTempCByIndex(0)); // Czujnik nr 0 w °C
  delay(500);
}
```

Zapis `sensors.getTempCByIndex(0)` oznacza pobranie temperatury z **pierwszego** czujnika (numerowane od 0). Drugi czujnik to `getTempCByIndex(1)`. Dla Fahrenheita: `getTempFByIndex(0)`.

Kompletny program:

<Code lang="cpp" file="ds18b20-podstawowy.ino">
```cpp
#include <OneWire.h>
#include <DallasTemperature.h>

const byte PIN_DS18B20 = A5;

OneWire oneWire(PIN_DS18B20);        // Linia 1-Wire na pinie A5
DallasTemperature sensors(&oneWire); // Inicjalizacja biblioteki

void setup() {
  Serial.begin(9600);
  sensors.begin(); // Inicjalizacja czujników
}

void loop() {
  sensors.requestTemperatures();  // Pobierz temperatury
  Serial.print("Aktualna temperatura: ");
  Serial.println(sensors.getTempCByIndex(0)); // Pierwszy czujnik, stopnie Celsjusza
  delay(500);
}
```
</Code>

## 9. Termometr MAX/MIN — wersja ulepszona

W poprzedniej sekcji inicjalizowaliśmy `tempMIN = 150`. Elegantsze rozwiązanie: **w `setup()` wykonaj pierwszy odczyt** i użyj go jako wartości startowej dla obu zmiennych. Dzięki temu program jest niezależny od zakresu czujnika.

<Code lang="cpp" file="ds18b20-min-max.ino">
```cpp
#include <OneWire.h>
#include <DallasTemperature.h>

const byte PIN_DS18B20 = A5;

OneWire oneWire(PIN_DS18B20);
DallasTemperature sensors(&oneWire);

float tempMAX = 0; // Wartość startowa — zostanie nadpisana w setup()
float tempMIN = 0; // Wartość startowa — zostanie nadpisana w setup()

void setup() {
  Serial.begin(9600);
  sensors.begin();

  // Ustaw pierwszy odczyt jako jednoczesny punkt startu MAX i MIN
  sensors.requestTemperatures();
  tempMAX = sensors.getTempCByIndex(0);
  tempMIN = sensors.getTempCByIndex(0);
}

void loop() {
  sensors.requestTemperatures();
  float temperatura = sensors.getTempCByIndex(0);

  if (temperatura > tempMAX) {
    tempMAX = temperatura;
    Serial.print("Nowa wartosc max: ");
    Serial.print(tempMAX);
    Serial.println("*C");
  }

  if (temperatura < tempMIN) {
    tempMIN = temperatura;
    Serial.print("Nowa wartosc min: ");
    Serial.print(tempMIN);
    Serial.println("*C");
  }

  delay(500);
}
```
</Code>

## 10. Kilka czujników DS18B20 na jednym pinie

## 11. Unikalny adres każdego czujnika DS18B20

Podłączanie wielu czujników na jednej linii jest możliwe, ponieważ producent przypisał każdemu DS18B20 **unikalny adres 64-bitowy**. W większych projektach warto posługiwać się adresami zamiast indeksami — uniezależnia to program od kolejności podłączenia.

Aby odczytać adresy, otwórz przykład dołączony do biblioteki: **Plik → Przykłady → OneWire → DS18x20_Temperature**. Przed uruchomieniem zmień linię:

```cpp
OneWire ds(10);  // na płytce
```

na:

```cpp
OneWire ds(A5);  // nasz pin
```

### Korzystanie z adresu w programie

Deklarujemy obiekt typu `DeviceAddress` i wpisujemy odczytany adres:

Kompletny program z adresowaniem:

  sensors.begin();
}

  sensors.requestTemperatures();

  Serial.println(sensors.getTempC(termometrZewnetrzny)); // Odczyt po adresie

<Expandable title="Kiedy używać adresów, a kiedy indeksów?" heading="###">
**Indeksy** (`getTempCByIndex(0)`) są wygodne przy prostych projektach z jednym lub dwoma czujnikami. Problem: kolejność czujników może się zmienić po przepięciu przewodów lub zmianie napięcia zasilania.

**Adresy** (`getTempC(mojCzujnik)`) są niezawodne w instalacjach trwałych — np. jeśli czujniki są rozlokowane po całym budynku. Możesz nadać im opisowe nazwy (`termometrKuchnia`, `termometrPiwnica`) i program pozostaje czytelny niezależnie od kolejności podłączenia.
</Expandable>

### Funkcja `termometrRGB()`

Kluczowa jest funkcja wyświetlająca temperaturę. Zakres: od −40 do +40 °C (powyżej/poniżej — clipping). Używamy `map()` do przeliczenia temperatury na liczbę diod.

<Code lang="cpp" file="termometr-rgb.ino">
```cpp
#include <Adafruit_NeoPixel.h>
#include <OneWire.h>
#include <DallasTemperature.h>

const byte PIN_LED_STRIP = A0;  // linijka WS2812
const byte PIN_DS18B20   = A5;  // czujnik temperatury 1-Wire

Adafruit_NeoPixel linijka = Adafruit_NeoPixel(8, PIN_LED_STRIP, NEO_GRB + NEO_KHZ800);

OneWire oneWire(PIN_DS18B20);
DallasTemperature sensors(&oneWire);

// Wstaw własny adres czujnika odczytany z przykładu OneWire!
DeviceAddress termometrZewnetrzny = { 0x10, 0x7A, 0x31, 0x99, 0x1, 0x8, 0x0, 0x4A };

void setup() {
  Serial.begin(9600);
  sensors.begin();
  linijka.begin();
  linijka.show(); // Wyczyść linijkę przy starcie
}

void loop() {
  sensors.requestTemperatures();
  Serial.print("Aktualna temperatura: ");
  Serial.println(sensors.getTempC(termometrZewnetrzny));

  int tempLinijka = sensors.getTempC(termometrZewnetrzny); // int, bo nie potrzebujemy ułamków
  termometrRGB(tempLinijka);

  delay(500);
}

void termometrRGB(int temperatura) {
  // Ogranicz zakres do -40...+40 °C
  if (temperatura > 40) {
    temperatura = 40;
  } else if (temperatura < -40) {
    temperatura = -40;
  }

  linijka.clear(); // Wyczyść linijkę przed nowym wyświetlaniem

  if (temperatura >= 0) {
    // Wartości dodatnie — od dołu, na czerwono
    temperatura = map(temperatura, 0, 40, 1, 8); // Przelicz na liczbę diod (1–8)
    for (int i = 0; i < temperatura; i++) {
      linijka.setPixelColor(i, linijka.Color(255, 0, 0)); // Czerwony
    }
  } else {
    // Wartości ujemne — od góry, na niebiesko
    temperatura = map(temperatura, -40, 0, 1, 8); // Przelicz na liczbę diod (1–8)
    for (int i = 8; i > temperatura; i--) {
      linijka.setPixelColor(i, linijka.Color(0, 0, 255)); // Niebieski
    }
  }

  linijka.show(); // Wyślij dane do linijki
}
```
</Code>

## Podsumowanie

Czujnik analogowy **LM35** jest tani i prosty w podłączeniu — wymaga tylko trzech przewodów i odczytu ADC. Jego wady to ograniczony zakres (0–100 °C w podstawowej wersji), wrażliwość na zakłócenia przy długich przewodach i konieczność osobnego pinu ADC dla każdego sensora.

Czujnik cyfrowy **DS18B20** komunikuje się przez interfejs **1-Wire**: wiele czujników na jednym pinie, zakres od −50 do +125 °C i cyfrowa odporność na zakłócenia. Cena jest wyższa, ale biblioteki `OneWire` i `DallasTemperature` ukrywają całą złożoność protokołu. Każdy DS18B20 ma **unikalny 64-bitowy adres** — to pozwala jednoznacznie identyfikować czujniki nawet przy rozbudowanych instalacjach. Projekt termometru RGB pokazuje, jak funkcja `map()` pozwala płynnie przeliczać zakres temperatur na liczbę świecących diod — technikę przydatną wszędzie tam, gdzie chcemy wizualizować wartość ciągłą na dyskretnej skali.
