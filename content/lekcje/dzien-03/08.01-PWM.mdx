W poprzedniej lekcji mierzyliśmy sygnały analogowe za pomocą ADC (Analog-Digital Converter). Teraz pójdziemy w drugą stronę: nauczymy się generować sygnał, który pozwala cyfrowemu Arduino uzyskać efekt płynnej regulacji. Będzie to PWM (Pulse Width Modulation, modulacja szerokości impulsu).

<Callout type="note" title="Kierunek działania">
ADC zamieniał napięcie analogowe na liczbę. PWM działa odwrotnie z punktu widzenia efektu: program podaje liczbę, a pin Arduino bardzo szybko przełącza się między `HIGH` i `LOW`, tworząc wrażenie płynnej regulacji mocy.
</Callout>

## 1. Czym jest sygnał PWM

Zacznijmy od zwykłego migania diodą. Jeżeli przez sekundę podajemy na pin `HIGH`, a przez kolejną sekundę `LOW`, to na wyjściu powstaje przebieg prostokątny. Dioda przez połowę czasu świeci, a przez połowę czasu jest zgaszona.

<Code lang="cpp" file="miganie-50-procent.ino">
```cpp
const byte PIN_LED = 3;

void setup() {
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  digitalWrite(PIN_LED, HIGH);
  delay(1000);

  digitalWrite(PIN_LED, LOW);
  delay(1000);
}
```
</Code>

**Okres** to czas jednego pełnego cyklu sygnału.  
**Wypełnienie** mówi, przez jaką część tego cyklu sygnał pozostaje w stanie wysokim.

Jeśli wydłużymy czas świecenia i skrócimy czas zgaszenia, wypełnienie wzrośnie. Okres może pozostać taki sam, ale średni efekt działania sygnału będzie inny.

</Code>

PWM polega właśnie na szybkim przełączaniu sygnału prostokątnego i regulacji jego wypełnienia. Jeżeli dzieje się to wystarczająco szybko, dioda nie wygląda jak migająca, tylko jak świecąca słabiej albo mocniej. Podobnie silnik może pracować wolniej albo szybciej, bo dostaje energię tylko przez część czasu.

<Task title="Zadanie — zmiana jasności LED przez wypełnienie" estimate="15 min">
W tym zadaniu zbudujemy własny programowy PWM (Software PWM) aby kontrolować jasność diody LED.
Podłącz diodę LED z rezystorem do pinu `3`. Wgraj poniższy szkic i obserwuj jak świeci dioda.

<Code lang="cpp" file="pwm-reczne-10ms.ino">
```cpp
const byte PIN_LED = 3;

void setup() {
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  digitalWrite(PIN_LED, HIGH);
  delay(1);

  digitalWrite(PIN_LED, LOW);
  delay(9);
}
```
</Code>

Okres sygnału wynosi tu `10 ms` (1 ms + 9 ms), a wypełnienie `10%`. Zmień wartości opóźnień tak, aby wypełnienie wynosiło `50%`, a następnie `90%`. Sprawdź jak zmienia się jasność diody.

Następnie przepisz szkic używając `delayMicroseconds()` zamiast `delay()`. Dzięki temu uzyskasz dokładniejszą kontrolę nad krótkimi impulsami. Przykład z wypełnieniem `0,5%` (50 µs stanu wysokiego na 9600 µs okresu):

<Code lang="cpp" file="pwm-reczne-delayMicroseconds.ino">
```cpp
const byte PIN_LED = 3;

void setup() {
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  digitalWrite(PIN_LED, HIGH);
  delayMicroseconds(50);

  digitalWrite(PIN_LED, LOW);
  delayMicroseconds(9550);
}
```
</Code>

1. Zmień wartość `50` na `500`, `1000`, `5000`. Jak zmienia się jasność diody? Jaki wniosek możesz wyciągnąć o zależności między wypełnieniem a jasnością?
2. Zmień Pin z `3` na `2` i uruchom program. Jak widzicie pin `2` nie ma symbolu `~`. Dlaczego wciąż możemy regulować jasność diody? 
Żeby zrozumieć przeczytaj sekcję "Głębiej: częstotliwość sprzętowego PWM w Arduino UNO"  poniżej.

</Task>

<Expandable title="Głębiej: częstotliwość sprzętowego PWM w Arduino UNO" heading="####">
W powyższych przykładach używamy opóźnień jednej sekundy i dioda widocznie miga. Sprzętowy PWM na pinach oznaczonych `~` działa domyślnie znacznie szybciej: piny `3`, `9`, `10`, `11` generują sygnał z częstotliwością **490 Hz**, a piny `5` i `6` — **980 Hz**. Jeden cykl trwa odpowiednio około `2 ms` i `1 ms` — zbyt szybko, żeby ludzkie oko mogło śledzić miganie.

Częstotliwość ma znaczenie praktyczne: dla diod LED 490 Hz jest wystarczające. Silniki DC (Direct Current, prąd stały) pracują ciszej i sprawniej przy wyższych częstotliwościach, bo cewki i elementy mechaniczne mniej drgają. Dla serwomechanizmów biblioteka `Servo` generuje własne impulsy `20 ms` niezależnie od sprzętowego PWM.

</Expandable>

<Expandable title="Głębiej: Dlaczego pin `2` działa z naszym kodem, choć nie ma symbolu `~`?" heading="####">

W zadaniu sterujemy jasnością diody przez ręczne wpisywanie bardzo krótkich `digitalWrite(HIGH)` i `digitalWrite(LOW)` z `delayMicroseconds()`. To jest **programowy PWM (Software PWM)**: główny procesor Arduino sam włącza i wyłącza pin, wykonując po kolei kolejne linie kodu. Nie potrzebuje żadnych specjalnych układów — każdy pin może to robić. Dlatego pin `2` bez `~` działa tak samo jak pin `3` z `~` w tym ćwiczeniu.

**Sprzętowy PWM jest zupełnie innym mechanizmem.** Funkcja `analogWrite()` deleguje generowanie sygnału do wbudowanych modułów mikrokontrolera zwanych **Timerami**. Timer to mały, niezależny licznik, który tyka z częstotliwością 16 MHz i sam zmienia stan pinu bez angażowania głównego procesora. Processor w tym czasie wykonuje inne zadania.

W sercu Arduino UNO R3, układzie **ATmega328P**, inżynierowie firmy Microchip umieścili dokładnie **trzy Timery**, a każdy z nich ma dwa fizyczne kanały wyjściowe. Te kanały są na stałe, krzemowymi ścieżkami, połączone z konkretnymi pinami:

<Table
  caption="Timery ATmega328P i przypisane do nich piny PWM"
  headers={["Timer", "Typ", "Piny"]}
  rows={[
    ["Timer0", "8-bitowy", <><strong>5</strong>, <strong>6</strong></>],
    ["Timer1", "16-bitowy", <><strong>9</strong>, <strong>10</strong></>],
    ["Timer2", "8-bitowy", <><strong>3</strong>, <strong>11</strong></>],
  ]}
/>

Matematyka jest nieubłagana: 3 Timery × 2 kanały = **6 sprzętowych wyjść PWM**. To właśnie te piny oznaczone `~`. Pin `2` nie jest fizycznie podłączony do żadnego Timera — brakuje mu krzemowej ścieżki wewnątrz układu scalonego.

Kiedy wywołasz `analog3Write(2, 128)`, oprogramowanie Arduino widzi brak połączenia z Timerem i po prostu ignoruje polecenie PWM (pin zachowuje się jak zwykłe `digitalWrite`). Żeby mieć sprzętowy PWM, musisz użyć pinu z `~`.

<Callout type="note" title="Timer0 a funkcje millis() i delay()">
Timer0 jest domyślnie używany przez Arduino do odliczania czasu — bez niego `millis()`, `micros()` i `delay()` przestałyby działać. Sterowanie jasnością przez pin `5` lub `6` nadal działa, ale jeśli kiedyś zmienisz ustawienia Timer0 ręcznie (przez rejestry), zaburzysz odmierzanie czasu.
</Callout>
</Expandable>

## 2. Do czego używamy PWM

PWM jest bardzo popularny, bo pozwala sterować elementami wykonawczymi z poziomu układu cyfrowego. Arduino nadal wystawia tylko `LOW` albo `HIGH`, ale zmienia proporcje czasu między tymi stanami.

<Table
  caption="Typowe zastosowania PWM"
  headers={["Zastosowanie", "Co regulujemy", "Co obserwujemy"]}
  rows={[
    ["Dioda LED", "Jasność", "Dioda świeci słabiej lub mocniej"],
    ["Silnik DC", "Średnią moc", "Silnik obraca się wolniej lub szybciej"],
    ["Serwomechanizm", "Szerokość impulsu sterującego", "Wał ustawia się pod zadanym kątem"],
  ]}
/>

<Callout type="tip" title="PWM nie jest prawdziwym napięciem analogowym">
Na pinie nadal pojawia się tylko `0 V` albo około `5 V`. Zmienia się czas trwania stanu wysokiego. Wiele elementów reaguje na wartość średnią takiego sygnału, dlatego efekt przypomina regulację analogową.
</Callout>

## 3. Piny PWM i funkcja `analogWrite()`

Arduino UNO ma kilka pinów sprzętowego PWM. Na płytce są one oznaczone tyldą `~`. Sprzętowy PWM oznacza, że mikrokontroler potrafi generować taki sygnał samodzielnie, bez ręcznego wpisywania bardzo krótkich `delay()` w programie.

<Schematic
  src="/img/lekcje/08.05-arduino-uno-pinout-pwm.png"
  caption="Piny PWM Arduino UNO są oznaczone symbolem tyldy przy numerze pinu."
  alt="Pinout Arduino UNO z pinami obsługującymi PWM"
  width={650}

/>

Do generowania PWM używamy funkcji `analogWrite(pin, wartosc)`. Nazwa może być myląca: nie tworzy ona prawdziwego napięcia analogowego, tylko sygnał PWM. Wartość mieści się w zakresie `0`-`255`, bo PWM w Arduino UNO jest 8-bitowy.

<Table
  caption="Zakres funkcji analogWrite()"
  headers={["Wartość", "Wypełnienie", "Efekt dla diody LED"]}
  rows={[
    ["0", "0%", "Dioda zgaszona"],
    ["64", "około 25%", "Dioda świeci słabo"],
    ["128", "około 50%", "Dioda świeci średnio"],
    ["255", "100%", "Dioda świeci pełną jasnością"],
  ]}
/>

<Expandable title="Głębiej: 8 bitów PWM kontra 10 bitów ADC" heading="####">
`analogRead()` zwraca wartości `0`–`1023` (10-bitowa rozdzielczość), natomiast `analogWrite()` przyjmuje wartości `0`–`255` (8-bitowa rozdzielczość). Ta asymetria bywa myląca.

ADC ma wyższą rozdzielczość, bo precyzja pomiaru jest ważna — 10-bitowy ADC mierzy napięcie z krokiem około `4,9 mV`. Dla wyjścia PWM 8 bitów daje 256 kroków jasności albo prędkości, co w praktyce jest wystarczające (ludzkie oko nie odróżni 1024 odcieni jasności od 256).

Gdy chcesz sterować serwem lub silnikiem wartością odczytaną przez `analogRead()`, musisz przeskalować zakresy. Użyj `map(odczyt, 0, 1023, 0, 255)` albo po prostu podziel wynik przez `4`.
</Expandable>

## 4. Sterowanie jasnością diody LED z pinów PWM za pomocą funkcji analogWrite()

Pierwszy praktyczny układ jest prosty: dioda LED z rezystorem podłączona do pinu `3`, czyli jednego z pinów PWM. Będziemy stopniowo zwiększać wypełnienie sygnału, aby dioda płynnie się rozjaśniała.

<Schematic
  src="/img/lekcje/08.06-dioda-led-sterowanie-pwm.png"
  caption="Dioda LED podłączona do pinu 3 pozwala sprawdzić działanie PWM w praktyce."
  alt="Schemat Arduino z diodą LED sterowaną sygnałem PWM na pinie 3"
  width={464}
  height={341}
/>

<Code lang="cpp" file="pwm-rozjasnianie-led.ino">
```cpp
const byte diodaPIN = 3;

int wypelnienie = 0;
int zmiana = 5;

void setup() {
  pinMode(diodaPIN, OUTPUT);
}

void loop() {
  analogWrite(diodaPIN, wypelnienie);

  if (wypelnienie < 255) {
    wypelnienie = wypelnienie + zmiana;
  } else {
    wypelnienie = 0;
  }

  delay(50);
}
```
</Code>

Program zwiększa wypełnienie co `50 ms`. Gdy dojdzie do wartości bliskiej pełnej jasności, wraca do zera i zaczyna rozjaśnianie od początku. To najprostszy sposób pokazania, że PWM może sterować „siłą" działania elementu.

<Task title="Zadanie 1" estimate="10 min">
Spróbuj uprościć powyższy program, tak aby nie trzeba było korzystać z instrukcji warunkowej if. Podpowiedź: zastanów się jaki wpływ na działanie programu ma typ zmiennej wypełnienie.
</Task>

<Task title="Zadanie 2" estimate="15 min">
Napisz program, który po zwiększeniu wypełnienia do `255` zacznie je stopniowo zmniejszać do zera (i tak w koło). Sprawdź przy jakim opóźnieniu w każdym obiegu pętli można zaobserwowany efekt pulsowania będzie najciekawszy.
</Task>

<Task title="Zadanie 3 — regulator jasności LED przez UART" estimate="15 min">
Podłącz LED do **pinu 9** (ten pin obsługuje PWM). Odbierz przez UART liczbę od 0 do 255 za pomocą `Serial.parseInt()`, a następnie ustaw jasność LED funkcją `analogWrite(pinLed, jasnosc)`. Wyślij potwierdzenie: `"Jasnosc ustawiona na: 128"`.

Jeśli wpisana liczba przekracza zakres 0–255, zamiast ustawiać jasność wypisz komunikat o błędzie.

Wskazówka: `analogWrite(pin, wartosc)` przyjmuje wartość 0–255.
</Task>

<Expandable title="Rozwiązanie Zadania 3" heading="####">
```cpp
const byte pinLed = 9;  // pin z obsługą PWM (tyldą ~ przy numerze)

void setup() {
  Serial.begin(9600);
  pinMode(pinLed, OUTPUT);
  Serial.println("Wpisz jasnosc LED (0-255):");
}

void loop() {
  if (Serial.available() > 0) {
    int jasnosc = Serial.parseInt();

    if (jasnosc < 0 || jasnosc > 255) {
      Serial.println("Blad: wpisz liczbe od 0 do 255.");
    } else {
      analogWrite(pinLed, jasnosc);
      Serial.print("Jasnosc ustawiona na: ");
      Serial.println(jasnosc);
    }

    while (Serial.available()) Serial.read();
  }
}
```
</Expandable>

## Podsumowanie

PWM pozwala cyfrowemu Arduino uzyskać efekt płynnej regulacji przez szybkie przełączanie pinu między stanami `HIGH` i `LOW`. Wypełnienie sygnału decyduje o średnim efekcie: jasności diody, prędkości silnika albo pozycji interpretowanej przez serwo. Piny oznaczone `~` obsługują sprzętowy PWM — wywołaj `analogWrite(pin, 0–255)` i timer mikrokontrolera wykona resztę bez angażowania procesora. Programowy PWM działa na dowolnym pinie, ale blokuje procesor na czas generowania impulsów.
