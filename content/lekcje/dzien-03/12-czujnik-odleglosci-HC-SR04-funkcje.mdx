## 1. Własne funkcje bez argumentów

Do tej pory cały kod umieszczaliśmy w `setup()` i `loop()`. Gdy program zaczyna rosnąć, warto wydzielić powtarzające się fragmenty do osobnych funkcji. Funkcja to nazwany blok kodu, który wywołujemy jedną linią zamiast kopiować kilkanaście.

Poniżej prosty program migający diodą — najpierw bez funkcji:

<Code lang="cpp" file="blink-bez-funkcji.ino">
```cpp
void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  digitalWrite(13, HIGH);
  delay(1000);
  digitalWrite(13, LOW);
  delay(1000);
}
```
</Code>

Teraz ten sam efekt z własną funkcją `zamigajLED()`:

<Code lang="cpp" file="blink-funkcja.ino">
```cpp
void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  zamigajLED();
}

void zamigajLED() {
  digitalWrite(13, HIGH);
  delay(500);
  digitalWrite(13, LOW);
  delay(500);
}
```
</Code>

Słowo `void` przed nazwą oznacza, że funkcja nie zwraca żadnej wartości. Ciało funkcji (kod między `{` a `}`) wykonuje się za każdym razem, gdy napiszemy `zamigajLED()`.

<Callout type="note" title="Gdzie umieszczać definicje funkcji?">
Funkcję możesz zdefiniować przed `setup()` lub po `loop()` — Arduino IDE nie wymaga wcześniejszej deklaracji. Dla czytelności warto trzymać `setup()` i `loop()` na górze, a pomocnicze funkcje poniżej.
</Callout>

<Task title="Zadanie 1" estimate="5 min">
Przepisz program z lekcji o miganiu diodą tak, żeby sekwencja migania była w osobnej funkcji `migaj()`. Wywołaj ją z `loop()`.
</Task>

## 2. Funkcje z argumentami

Funkcja z argumentem przyjmuje wartość z zewnątrz. Zamiast mieć kilka prawie-takich-samych funkcji dla różnych czasów migania, piszemy jedną z parametrem:

<Code lang="cpp" file="blink-z-argumentem.ino">
```cpp
void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  zamigajLED(50);
}

void zamigajLED(int czas) {
  digitalWrite(13, HIGH);
  delay(czas);
  digitalWrite(13, LOW);
  delay(czas);
}
```
</Code>

Wartość `50` przekazana przy wywołaniu trafia do zmiennej `czas` wewnątrz funkcji. Możemy teraz wywołać `zamigajLED(100)` albo `zamigajLED(500)` i za każdym razem dioda mignie inaczej.

### Wiele argumentów

Dodajmy drugi argument — liczbę mignięć:

<Code lang="cpp" file="blink-dwa-argumenty.ino">
```cpp
void setup() {
  pinMode(13, OUTPUT);
  zamigajLED(100, 5);
}

void loop() {
}

void zamigajLED(int czas, int ile) {
  for (int i = 0; i < ile; i++) {
    digitalWrite(13, HIGH);
    delay(czas);
    digitalWrite(13, LOW);
    delay(czas);
  }
}
```
</Code>

Trzeci argument może wskazywać numer pinu, co pozwala sterować różnymi diodami tą samą funkcją:

<Code lang="cpp" file="blink-trzy-argumenty.ino">
```cpp
void setup() {
  zamigajLED(100, 5, 13);
  zamigajLED(150, 4, 8);
}

void loop() {
}

void zamigajLED(int czas, int ile, int pin) {
  pinMode(pin, OUTPUT);

  for (int i = 0; i < ile; i++) {
    digitalWrite(pin, HIGH);
    delay(czas);
    digitalWrite(pin, LOW);
    delay(czas);
  }
}
```
</Code>

</Task>

## 3. Funkcje zwracające wynik

Funkcja może nie tylko coś robić, ale też oddać wynik do miejsca wywołania. Deklarujemy wtedy typ zwracany (np. `int`) zamiast `void`, a wewnątrz używamy `return`:

<Code lang="cpp" file="funkcja-zwracajaca.ino">
```cpp
void setup() {
  Serial.begin(9600);
}

void loop() {
  int wynik = kwadratPole(4);
  Serial.println(wynik);
  delay(500);
}

int kwadratPole(int a) {
  return a * a;
}
```
</Code>

Możemy też wstawić wywołanie bezpośrednio w argumencie `Serial.println()`:

```cpp
Serial.println(kwadratPole(4));
```

Funkcja zwracająca wartość sprawdza się wszędzie tam, gdzie potrzebujemy obliczyć coś i użyć wyniku w dalszej logice — na przykład przy pomiarze odległości.

<Expandable title="Interaktywny przykład — pole kwadratu z UART (Universal Asynchronous Receiver-Transmitter)" heading="####">

Program czyta liczbę wpisaną w Monitorze portu szeregowego, oblicza pole kwadratu i odpowiada wynikiem:

```cpp
String odebraneDane = "";

void setup() {
  Serial.begin(9600);
}

void loop() {
  if (Serial.available() > 0) {
    odebraneDane = Serial.readStringUntil('\n');
    int wynik = kwadratPole(odebraneDane.toInt());
    Serial.println(wynik);
  }
}

int kwadratPole(int a) {
  return a * a;
}
```

Wpisz `5` w terminalu — powinieneś otrzymać `25`.

</Expandable>

### Zasada działania

1. Na pin `Trig` podajemy impuls wysoki trwający **10 µs (mikrosekundy)** — czujnik wysyła 8 impulsów ultradźwiękowych.
2. Pin `Echo` przechodzi w stan wysoki i pozostaje tam przez czas proporcjonalny do zmierzonej odległości.
3. Mierzymy czas trwania stanu wysokiego na `Echo` — to czas podróży dźwięku (tam i z powrotem).
4. Dzielimy przez `58`, żeby otrzymać odległość w centymetrach.

<Expandable title="Ograniczenia i martwa strefa czujnika HC-SR04" heading="####">

HC-SR04 to prosty i tani czujnik, ale ma kilka praktycznych ograniczeń:

- **Martwa strefa:** obiekt bliższy niż ok. `2–3 cm` nie zostanie wykryty — echo wraca zbyt szybko, zanim czujnik zdąży przełączyć się w tryb nasłuchiwania.
- **Maksymalny zasięg:** producent deklaruje ok. `400 cm`, ale powyżej `200–250 cm` pomiary stają się niestabilne.
- **Kąt wiązki:** czujnik „widzi" stożek o półkącie ok. `15°`. Obiekt pod dużym skosem może odbić sygnał w bok i nie wrócić do czujnika.
- **Materiały pochłaniające:** miękkie powierzchnie (tkaniny, piana, futro) pochłaniają ultradźwięki i zwracają słabe echo lub w ogóle go nie zwracają.
- **Fałszywe echa:** w pomieszczeniach z wieloma powierzchniami echo może wielokrotnie odbijać się od ścian. `pulseIn()` chwyta pierwsze echo — zazwyczaj poprawne, ale przy skomplikowanej geometrii mogą pojawiać się skoki odczytu.

</Expandable>

Zaczynamy od podstawowego programu wyzwalającego pomiar:

<Code lang="cpp" file="hc-sr04-wyzwolenie.ino">
```cpp
#define trigPin 12
#define echoPin 11

void setup() {
  Serial.begin(9600);
  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);
}

void loop() {
  // Wyzwolenie pomiaru
  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);
}
```
</Code>

Teraz mierzymy czas echa funkcją `pulseIn()` i przeliczamy na centymetry:

<Code lang="cpp" file="hc-sr04-dystans-cm.ino">
```cpp
#define trigPin 12
#define echoPin 11

void setup() {
  Serial.begin(9600);
  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);
}

void loop() {
  long czas, dystans;

  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  czas = pulseIn(echoPin, HIGH);
  dystans = czas / 58;

  Serial.print(dystans);
  Serial.println(" cm");

  delay(500);
}
```
</Code>

<Callout type="note" title="Skąd wzięło się 58?">
Dźwięk przebywa w powietrzu ok. 340 m/s. Impuls pokonuje dystans dwukrotnie (tam i z powrotem), a `pulseIn()` zwraca czas w mikrosekundach. Dzielenie przez 58 daje przybliżenie odległości w centymetrach: 1 cm = 58 µs.
</Callout>

<Expandable title="Kompensacja temperatury — kiedy dzielnik 58 nie wystarczy" heading="####">

Prędkość dźwięku w powietrzu zależy od temperatury. Wzór przybliżony:

> v ≈ 331,3 + 0,606 × T [m/s]

Przy `20 °C` wynosi ok. `343 m/s`, a przy `0 °C` ok. `331 m/s`. Dzielnik `58` odpowiada temperaturze pokojowej — przy mrozie lub upale wynik jest nieco zaburzony.

Jeśli masz dostęp do czujnika temperatury (np. DHT11 z kolejnych lekcji), możesz na bieżąco przeliczać dzielnik:

```cpp
long zmierzOdlegloscDokl(float temperatura) {
  float v = 331.3 + 0.606 * temperatura; // m/s
  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);
  long czas = pulseIn(echoPin, HIGH);
  // czas [µs] * v [m/s] / 20000 → dystans [cm]
  return (long)(czas * v / 20000.0);
}
```

W sali szkolnej różnica temperatury między zimą a latem to ok. `20 °C`, co przekłada się na błąd pomiaru ok. `3%`. Przy zasięgu `100 cm` to ok. `3 cm` — często pomijalne, ale przy precyzyjnym omijaniu przeszkód warto mieć to z tyłu głowy.

</Expandable>

## 6. Funkcja zwracająca odległość

Zamknijmy cały pomiar w jednej funkcji — kod `loop()` będzie wtedy bardzo przejrzysty:

<Code lang="cpp" file="hc-sr04-funkcja.ino">
```cpp
#define trigPin 12
#define echoPin 11

void setup() {
  Serial.begin(9600);
  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);
}

void loop() {
  Serial.print(zmierzOdleglosc());
  Serial.println(" cm");
  delay(500);
}

int zmierzOdleglosc() {
  long czas, dystans;

  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  czas = pulseIn(echoPin, HIGH);
  dystans = czas / 58;

  return dystans;
}
```
</Code>

<Task title="Zadanie 3" estimate="10 min">
Uruchom powyższy program i powoli przybliżaj dłoń do czujnika. Sprawdź, czy wyniki w Monitorze portu szeregowego zmieniają się płynnie. Następnie zapisz wynik do zmiennej i wydrukuj go ze słowem `"Odleglosc: "` przed wartością.
</Task>

<Expandable title="Uśrednianie pomiarów — stabilniejsze wskazania" heading="####">

Pojedynczy odczyt HC-SR04 może czasem „skoczyć" o kilka centymetrów z powodu przypadkowego echa lub drgań zasilania. Uśrednianie kilku pomiarów znacząco poprawia stabilność:

```cpp
int zmierzOdlegloscUsredniona(int probek) {
  long suma = 0;
  for (int i = 0; i < probek; i++) {
    suma += zmierzOdleglosc();
    delay(20);
  }
  return suma / probek;
}
```

Wywołanie `zmierzOdlegloscUsredniona(5)` pobiera `5` pomiarów i zwraca ich średnią. Jedno `delay(20)` to `20 ms` przerwy między próbkami — pięć próbek zajmuje łącznie ok. `100 ms`. Im więcej próbek, tym wolniejsza reakcja programu. W robotach mobilnych `3`–`5` pomiarów to zazwyczaj dobry kompromis między stabilnością odczytu a szybkością reagowania na przeszkody.

</Expandable>

## 7. Sprawdzanie zakresu odległości

Możemy napisać funkcję `zakres()`, która sprawdza, czy zmierzona odległość mieści się w podanym przedziale, i reaguje stanem pinu (np. buzzera lub diody):

<Code lang="cpp" file="hc-sr04-zakres.ino">
```cpp
void zakres(int a, int b) {
  int jakDaleko = zmierzOdleglosc();
  if ((jakDaleko > a) && (jakDaleko < b)) {
    digitalWrite(2, HIGH);
  } else {
    digitalWrite(2, LOW);
  }
}
```
</Code>

## Podsumowanie

Własne funkcje porządkują kod: wydzielasz powtarzające się bloki, nadajesz im nazwy i możesz wielokrotnie wywoływać jedną linijką. Argumenty sprawiają, że funkcja jest elastyczna — jeden fragment kodu działa dla różnych wartości. Funkcja zwracająca wynik pozwala użyć obliczonej wartości tam, gdzie jej potrzebujesz.

Czujnik HC-SR04 mierzy odległość ultradźwiękami: krótki impuls na `Trig`, pomiar czasu echa na `Echo` przez `pulseIn()`, przeliczenie przez `58` — i masz odległość w centymetrach. Zamknięcie pomiaru w funkcji `zmierzOdleglosc()` dało przejrzysty program alarmu zbliżeniowego, w którym `loop()` robi jedną rzecz: sprawdza zakres.
