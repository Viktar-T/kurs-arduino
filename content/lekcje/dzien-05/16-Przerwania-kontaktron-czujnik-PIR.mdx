W tej lekcji poznasz dwa popularne czujniki alarmowe: **kontaktron** (czujnik drzwiowy/okienny) i **czujnik ruchu PIR HC-SR501**. Nauczysz się też korzystać z **przerwań sprzętowych** — mechanizmu pozwalającego Arduino natychmiast reagować na zdarzenia zewnętrzne bez nieustannego sprawdzania stanu wejść w pętli głównej.

## 1. Kontaktron — czujnik alarmowy drzwi i okien

Kontaktron to prosty czujnik alarmowy składający się z dwóch części: **rurki ze stalowym przełącznikiem trzcinowym** (montowanej na ościeżnicy) i **magnesu** (przyklejanego do skrzydła okna lub drzwi).

<Photo

Gdy magnes zbliży się do rurki, wewnętrzne styki zamykają się i prąd może przepływać. Z punktu widzenia Arduino kontaktron działa **dokładnie jak przycisk** — tyle że nie naciskamy go ręcznie. Nawet minimalne uchylenie okna odsuwa magnes i rozrywa obwód, wyzwalając alarm.

### Schemat połączeń

- **LED_R** → rezystor 1 kΩ → pin **10**
- **LED_G** → rezystor 1 kΩ → pin **11**
- **LED_B** → rezystor 1 kΩ → pin **12**
- Wspólna katoda RGB → **GND**
- Kontaktron (pin 1) → pin **0** Arduino
- Kontaktron (pin 2) → **GND**

### Pierwszy program z kontaktronem

Używamy trybu **INPUT_PULLUP** — wbudowany rezystor podciągający utrzymuje pin 0 w stanie HIGH, gdy kontaktron jest rozwarty (okno otwarte). Zbliżenie magnesu (okno zamknięte) ściąga pin do LOW.

<Code lang="cpp" file="kontaktron-led.ino">
```cpp
const byte LED_R = 10;
const byte LED_G = 11;
const byte LED_B = 12;
const byte KONTAKTRON = 0;

void setup() {
  pinMode(LED_R, OUTPUT);
  pinMode(LED_G, OUTPUT);
  pinMode(LED_B, OUTPUT);
  pinMode(KONTAKTRON, INPUT_PULLUP); // Wbudowany rezystor podciągający

  digitalWrite(LED_R, LOW);
  digitalWrite(LED_G, LOW);
  digitalWrite(LED_B, LOW);
}

void loop() {
  if (digitalRead(KONTAKTRON) == LOW) {
    // Magnes blisko — okno zamknięte — dioda zielona
    digitalWrite(LED_R, LOW);
    digitalWrite(LED_G, HIGH);
  } else {
    // Magnes daleko — okno otwarte — dioda czerwona ALARM
    digitalWrite(LED_R, HIGH);
    digitalWrite(LED_G, LOW);
  }
}
```
</Code>

<Task title="Zadanie 4.1 — alarm, który się nie wyłącza" estimate="10 min">
Podłącz buzzer do układu. Napisz program, który:
- włącza alarm (buzzer + czerwona LED) natychmiast po otwarciu okna (rozwarciu kontaktronu),
- alarm **nie wyłącza się** po ponownym zamknięciu okna — wymaga ręcznego resetu Arduino.

Wskazówka: użyj zmiennej logicznej `bool alarmWyzwolony = false;`.

## 2. Czujnik PIR HC-SR501

PIR (Passive InfraRed — pasywna podczerwień) wykrywa ruch na podstawie zmian promieniowania podczerwonego (ciepła) w polu widzenia. „Pasywny" oznacza, że sam niczego nie emituje — jedynie mierzy różnice temperatury otoczenia. Nawet ciepłe powietrze z uchylonego okna może wyzwolić tańsze modele.

<Expandable title="Głębiej: dlaczego PIR wykrywa ruch, a nie samą obecność?" heading="####">

W module PIR znajdują się zwykle dwa małe elementy piroelektryczne połączone różnicowo. Stała temperatura tła daje podobny sygnał z obu części, więc elektronika traktuje ją jako stan spoczynku.

Ruch człowieka powoduje szybką zmianę rozkładu promieniowania podczerwonego: najpierw jedna część sensora widzi cieplejszy obiekt, potem druga. Układ wykrywa właśnie tę zmianę, a soczewka Fresnela dzieli pole widzenia na wiele stref, żeby nawet niewielkie przesunięcie człowieka dawało wyraźny impuls.

Z tego powodu PIR może nie reagować na osobę siedzącą bez ruchu, ale może zareagować na ciepłe powietrze z kaloryfera, przeciąg z okna albo nagłą zmianę oświetlenia słonecznego na obudowie czujnika.

</Expandable>

### Tryby pracy HC-SR501

Jumper na płytce pozwala wybrać jeden z dwóch trybów:

- **Retriggering (domyślny)** — wyjście pozostaje HIGH tak długo, jak ruch jest wykrywany + czas ustawiony przez Tx. Każde nowe wykrycie ruchu przedłuża sygnał HIGH.
- **Non-retriggering** — wyjście idzie w HIGH jednorazowo i opada do LOW niezależnie od dalszego ruchu.

### Program z czujnikiem PIR

<Code lang="cpp" file="pir-led.ino">
```cpp
const byte LED_R = 10;
const byte LED_G = 11;
const byte LED_B = 12;
const byte KONTAKTRON = 0;
const byte PIR = 2;

void setup() {
  pinMode(LED_R, OUTPUT);
  pinMode(LED_G, OUTPUT);
  pinMode(LED_B, OUTPUT);
  pinMode(KONTAKTRON, INPUT_PULLUP);
  pinMode(PIR, INPUT);

  digitalWrite(LED_R, LOW);
  digitalWrite(LED_G, LOW);
  digitalWrite(LED_B, LOW);
}

void loop() {
  if (digitalRead(PIR) == LOW) {
    // Brak ruchu — dioda zielona
    digitalWrite(LED_R, LOW);
    digitalWrite(LED_G, HIGH);
  } else {
    // Wykryto ruch — dioda czerwona
    digitalWrite(LED_R, HIGH);
    digitalWrite(LED_G, LOW);
  }
}
```
</Code>

## 3. Po co przerwania?

Budując bardziej rozbudowane programy, szybko napotkasz problem: Arduino sprawdza stan czujnika dopiero wtedy, gdy dotrze do odpowiedniej linii w `loop()`. Jeśli wcześniej jest `delay(1000)` lub długie obliczenia, Arduino może przeoczyć krótkie zdarzenie.

<Photo
  file="16.12-analogia-gotowanie-zupy.jpg"
  caption="Plan na dziś: gotujemy zupę! Wyobraź sobie, że co chwilę przerywasz gotowanie, żeby podejść do okna i sprawdzić, czy kurier już jedzie."
  alt="Garnek z gotującą się zupą — ilustracja analogii do pollingu czujnika"
  width={400}
  height={300}
/>

Wyobraź sobie: gotujesz zupę i czekasz na kuriera. Bez przerwań co chwilę przerywasz gotowanie, żeby podejść do okna i sprawdzić — nieefektywne i łatwo coś przegapić.

<Photo
  file="16.13-analogia-sasiadka.jpg"
  caption="Rozwiązanie: prosisz sąsiadkę, żeby obserwowała wejście i zapukała, gdy kurier przyjedzie. Ty gotujesz spokojnie."
  alt="Starsza kobieta przy oknie z lornetką — ilustracja mechanizmu przerwania sprzętowego"
  width={400}
  height={300}
/>

Lepszy sposób: prosisz sąsiadkę, żeby patrzyła przez okno i **zapukała**, gdy kurier przyjedzie. Ty gotujesz spokojnie i reagujesz dopiero na sygnał. Dokładnie tak działa **przerwanie sprzętowe** — specjalny mechanizm w tle monitoruje pin i gdy nastąpi zdefiniowane zdarzenie, natychmiast przerywa główny program i wywołuje Twoją funkcję obsługi.

<Photo
  file="16.14-analogia-alarm-zlodziej.jpg"
  caption="Czy alarm zdąży zauważyć szybkiego złodzieja? Tylko przerwanie gwarantuje natychmiastową reakcję — polling może nie zdążyć."
  alt="Złodziej wchodzący przez okno — ilustracja konieczności natychmiastowej reakcji na zdarzenie"
  width={400}
  height={300}
/>

### Kiedy stosować przerwania

- Gdy program ma `delay()` lub wiele zadań i nie może „czekać" na czujnik.
- Gdy wymagana jest **natychmiastowa** reakcja (alarm, licznik impulsów, enkoder).

### Kiedy przerwania nie są potrzebne

- W prostych, krótkich programach bez opóźnień.
- Gdy czas reakcji na zdarzenie nie jest krytyczny.



## 4. Przerwania w Arduino — attachInterrupt()

Arduino UNO obsługuje przerwania sprzętowe wyłącznie na pinach **2** (int.0) i **3** (int.1).

### Zasady pisania funkcji obsługi przerwania (ISR)

<Callout type="warning" title="Nigdy nie używaj delay() wewnątrz obsługi przerwania!">
ISR (Interrupt Service Routine — funkcja obsługi przerwania) musi wykonać się **błyskawicznie**. Umieszczenie `delay()` lub `delayMicroseconds()` w ISR **zatrzymuje cały program** na czas jej wykonania. Prowadzi to do nieprzewidywalnego zachowania układu i jest bardzo trudne do debugowania.
</Callout>

Reguły ISR:
- Nie przyjmuje argumentów i niczego nie zwraca.
- Wykonuje się jak najkrócej.
- **Bezwzględny zakaz** `delay()` i `delayMicroseconds()`.
- Unikaj długich obliczeń i pętli oczekujących.

## 5. Przykład 1 — przerwanie na wykrycie ruchu

Program świeci zieloną LED w spoczynku. Gdy PIR wykryje ruch, przerwanie natychmiast wywołuje funkcję `alarm()`, która zmienia kolor — bez czekania na kolejny obrót `loop()`.

<Code lang="cpp" file="pir-przerwanie-alarm.ino">
```cpp
const byte LED_R = 10;
const byte LED_G = 11;
const byte LED_B = 12;
const byte KONTAKTRON = 0;
const byte PIR = 2;

void setup() {
  pinMode(LED_R, OUTPUT);
  pinMode(LED_G, OUTPUT);
  pinMode(LED_B, OUTPUT);
  pinMode(KONTAKTRON, INPUT_PULLUP);
  pinMode(PIR, INPUT);

  digitalWrite(LED_R, LOW);
  digitalWrite(LED_G, HIGH); // Zielona — stan normalny
  digitalWrite(LED_B, LOW);

  // Rejestruj ISR na zboczu rosnącym pinu PIR
  attachInterrupt(digitalPinToInterrupt(PIR), alarm, RISING);
}

void loop() {
  // Pętla pusta — tylko przerwanie reaguje na ruch
}

void alarm() {
  // ISR — musi być krótka!
  digitalWrite(LED_R, HIGH);
  digitalWrite(LED_G, LOW);
}
```
</Code>

## 6. Przykład 2 — volatile i licznik wykryć

Gdy ISR musi przekazać informację do `loop()`, używamy zmiennej **globalnej** oznaczonej słowem kluczowym `volatile`. Bez `volatile` kompilator może zoptymalizować zmienną do **rejestru procesora** — `loop()` nie zobaczyłaby aktualnej wartości zmienionej przez ISR.

<Callout type="note" title="Słowo kluczowe volatile">
`volatile` informuje kompilator: „ta zmienna może być zmieniona poza normalnym tokiem programu (np. przez ISR) — zawsze czytaj jej wartość bezpośrednio z **pamięci RAM**, nie korzystaj z wartości zapisanej w **rejestrze procesora**."
</Callout>

<Expandable title="Głębiej: słowo kluczowe volatile" heading="####">

Kompilator optymalizuje kod, zakładając że **tylko bieżąca funkcja** zmienia lokalne i globalne zmienne. W pętli `loop()` może więc raz odczytać `ileRazy` do **rejestru procesora** i w kolejnych obrotach używać **starej wartości z rejestru** — bez ponownego zajrzenia do pamięci RAM.

Tymczasem ISR (`alarm()`) wykonuje się **w dowolnym momencie** — nawet w środku `loop()`. Dla mikrokontrolera to dwa fragmenty kodu współdzielące jedną zmienną, choć kompilator tego „nie widzi”.

`volatile` wyłącza taką optymalizację: **każdy** odczyt i zapis idzie bezpośrednio do RAM. Dzięki temu `loop()` widzi licznik zaktualizowany przez ISR.

**Czego `volatile` nie gwarantuje:**

- **Atomowości** — operacja `ileRazy++` to odczyt, dodanie 1 i zapis. ISR może przerwać ją w połowie, jeśli wywołasz ją też w `loop()`.
- **Bezpieczeństwa złożonych typów** — struktury czy tablice współdzielone z ISR wymagają dodatkowej ostrożności (krótka blokada przerwań: `noInterrupts()` … `interrupts()` albo kopiowanie do zmiennej lokalnej w `loop()`).

**Praktyka w tej lekcji:** ISR tylko inkrementuje prosty licznik (`ileRazy++`), a cała logika LED zostaje w `loop()`. To bezpieczny i czytelny wzorzec na start.

</Expandable>

<Code lang="cpp" file="pir-volatile-licznik.ino">
```cpp
const byte LED_R = 10;
const byte LED_G = 11;
const byte LED_B = 12;
const byte KONTAKTRON = 0;
const byte PIR = 2;

volatile int ileRazy = 0; // Współdzielona między loop() a ISR — musi być volatile

void setup() {
  pinMode(LED_R, OUTPUT);
  pinMode(LED_G, OUTPUT);
  pinMode(LED_B, OUTPUT);
  pinMode(KONTAKTRON, INPUT_PULLUP);
  pinMode(PIR, INPUT);

  digitalWrite(LED_R, LOW);
  digitalWrite(LED_G, HIGH);
  digitalWrite(LED_B, LOW);

  attachInterrupt(digitalPinToInterrupt(PIR), alarm, RISING);
}

void loop() {
  if (ileRazy < 3) {
    // Stan OK — zielona
    digitalWrite(LED_R, LOW);
    digitalWrite(LED_G, HIGH);
    digitalWrite(LED_B, LOW);
  } else if (ileRazy < 6) {
    // Ostrzeżenie — niebieska
    digitalWrite(LED_R, LOW);
    digitalWrite(LED_G, LOW);
    digitalWrite(LED_B, HIGH);
  } else {
    // ALARM — czerwona
    digitalWrite(LED_R, HIGH);
    digitalWrite(LED_G, LOW);
    digitalWrite(LED_B, LOW);
  }
}

void alarm() {
  ileRazy++; // ISR tylko inkrementuje licznik — reszta logiki w loop()
}
```

## 7. Przestroga — nie używaj delay() w ISR

<Photo
  file="16.17-timer-opoznienie-ostrzezenie.jpg"
  caption="Długi czas wykonywania ISR zatrzymuje cały program — każde wywołanie przerwania blokuje mikrokontroler."
  alt="Zegar — ilustracja problemu długotrwałego wykonywania ISR"
  width={700}
  height={400}
/>

Jeśli umieścisz `delay(5000)` wewnątrz ISR, **każde wykrycie ruchu zatrzymuje cały program na 5 sekund**. Jeśli w `loop()` masz `delay(1000)`, timing wszystkich operacji zacznie się kumulować i zachowanie układu stanie się nieprzewidywalne — bardzo trudne do debugowania.

**Złota zasada:** ISR tylko ustawia flagę lub inkrementuje licznik. Całą logikę (długie obliczenia, wyświetlanie, dźwięki) przenoś do `loop()`.

<Task title="Zadanie 4.3 — alarm po zakończeniu ruchu" estimate="15 min">
Napisz program, który wyzwala alarm **dopiero gdy ruch przestanie być wykrywany** (nie w momencie wykrycia). Przerwanie powinno reagować na zbocze **opadające** (FALLING), nie rosnące.

Pamiętaj, że HC-SR501 w trybie retriggering utrzymuje wyjście HIGH przez czas ustawiony przez Tx — ustaw go na minimum przed testowaniem.
</Task>

<Task title="Zadanie 4.4 — przełączanie LED" estimate="10 min">
Napisz program, w którym każde wykrycie ruchu **przełącza** stan diody (jeśli była wyłączona — włącza; jeśli była włączona — wyłącza). Użyj `volatile bool swiatlo = false;` i operatora `!` (negacja logiczna).
</Task>

## Podsumowanie

**Kontaktron** działa jak zwykły przycisk z `INPUT_PULLUP` — reaguje na zbliżenie lub odsunięcie magnesu. **Czujnik PIR HC-SR501** wykrywa zmiany temperatury podczerwieni w polu 120°; zasięg i czas sygnału HIGH regulujesz potencjometrami Sx i Tx. Gdy program ma `delay()` lub wiele zadań, sprawdzanie czujnika w `loop()` może przeoczyć krótkie zdarzenia — **przerwanie sprzętowe** (`attachInterrupt()`) gwarantuje natychmiastową reakcję niezależnie od aktywności pętli głównej. Arduino UNO obsługuje przerwania tylko na pinach **2** i **3**. Dobierz tryb wyzwalania do sytuacji: `RISING` dla zbocza rosnącego, `FALLING` dla opadającego, `CHANGE` dla obydwu. Zmienne dzielone między ISR a `loop()` zawsze oznaczaj jako `volatile`. **Nigdy nie używaj `delay()` wewnątrz ISR** — zatrzymuje cały mikrokontroler na czas wykonania funkcji.
