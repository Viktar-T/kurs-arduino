Diody świecące znajdują zastosowanie w każdym projekcie. Często oprócz prostej sygnalizacji stanu urządzenia zależy nam na efektach wizualnych. W tej lekcji poznamy dwa podejścia do sterowania kolorowymi diodami RGB (Red, Green, Blue):  
- klasyczne (trzy **osobne kanały**, PWM (Pulse Width Modulation))  
- nowoczesne (diody **programowalne WS2812** ze zintegrowanym sterownikiem i biblioteką NeoPixel).

## 1. Czym są diody programowalne?

Diody programowalne, nazywane czasem inteligentnymi, mogą być elementami zagadkowymi dla wielu początkujących. Jak objawia się ich „inteligencja"? W każdej diodzie WS2812 producent zamieścił miniaturowy układ sterujący, który potrafi odebrać dane z Arduino przez **jeden przewód sygnałowy** i na ich podstawie ustawić jasność trzech barw (R, G, B). Dzięki temu możemy kontrolować setki diod, używając tylko jednego pinu Arduino.

## 3. Diody RGB — podejście tradycyjne

Diody RGB (ang. *Red, Green, Blue*) mają w swoim wnętrzu trzy struktury świecące — czerwoną, zieloną i niebieską. Sterując niezależnie każdą z nich, możemy uzyskać dowolny kolor.

Diody RGB **ze wspólną katodą** mają jedną wspólną nóżkę masy (GND, Ground) — to najdłuższa nóżka. Trzy pozostałe odpowiadają kolejno: czerwonemu, zielonemu i niebieskiemu kanałowi.

<Expandable title="Głębiej: wspólna katoda kontra wspólna anoda — uważaj na zakup!" heading="####">
Producenci diod RGB oferują **dwa warianty** wewnętrznego połączenia. Wybór decyduje o tym, jak będziesz pisał kod — a wizualnie diody wyglądają identycznie.

**Wspólna katoda (CC, Common Cathode):**
- Najdłuższa nóżka idzie do **GND**.
- Każdy kolor zapalasz **stanem HIGH** na pinie.
- `digitalWrite(R, HIGH)` zapala czerwony.
- `analogWrite(R, 255)` to pełna jasność, `analogWrite(R, 0)` to wyłączenie.

**Wspólna anoda (CA, Common Anode):**
- Najdłuższa nóżka idzie do **+5V**.
- Każdy kolor zapalasz **stanem LOW** na pinie (prąd musi „wpłynąć" do Arduino).
- `digitalWrite(R, LOW)` zapala czerwony.
- `analogWrite(R, 0)` to pełna jasność, `analogWrite(R, 255)` to wyłączenie — **logika odwrócona!**

Najprostszy test bez patrzenia na dokumentację: podłącz najdłuższą nóżkę przez rezystor `1 kΩ` do `+5V` i kolejno dotykaj pozostałych nóżek przewodem od GND. Jeśli diody świecą — masz **wspólną anodę**. Jeśli nie — przekładasz wspólną nóżkę do GND i testujesz dotykając do +5V; wtedy to **wspólna katoda**.

W kodzie z lekcji używamy diody **wspólnej katody**. Jeśli kupiłeś przypadkiem wspólną anodę, zamień każde `analogWrite(R, wartosc)` na `analogWrite(R, 255 - wartosc)` i program zadziała poprawnie.
</Expandable>

### 3.1 Pierwsze użycie diody RGB

Podłącz diodę RGB do pinów 3, 5 i 6 (wszystkie obsługują PWM), każdy przez rezystor 1 kΩ. Masę podłącz do GND.

  alt="Schemat Fritzing: Arduino UNO, dioda RGB, trzy rezystory 1 kΩ"
  width={700}

Pierwszy szkic zaświeci każdy kolor po kolei, potem połączy je razem, a na końcu wyłączy wszystkie:

<Code lang="cpp" file="rgb-pierwsze-kolory.ino">
```cpp
const byte czerwona = 3;
const byte zielona = 5;
const byte niebieska = 6;

void setup() {
  pinMode(czerwona, OUTPUT); // Piny podłączone do diody jako wyjścia
  pinMode(zielona, OUTPUT);
  pinMode(niebieska, OUTPUT);
}

void loop() {
  digitalWrite(czerwona, HIGH);  // Świecimy tylko na czerwono
  delay(2000);
  digitalWrite(czerwona, LOW);   // Świecimy tylko na zielono
  digitalWrite(zielona, HIGH);
  delay(2000);
  digitalWrite(zielona, LOW);    // Świecimy tylko na niebiesko
  digitalWrite(niebieska, HIGH);
  delay(2000);
  digitalWrite(niebieska, LOW);

  digitalWrite(czerwona, HIGH);  // Świecimy każdą po kolei, bez gaszenia poprzednich
  delay(2000);
  digitalWrite(zielona, HIGH);
  delay(2000);
  digitalWrite(niebieska, HIGH);
  delay(2000);

  digitalWrite(czerwona, LOW);   // Wyłączamy wszystkie diody
  digitalWrite(niebieska, LOW);
  digitalWrite(zielona, LOW);
  delay(2000);
}
```
</Code>

### 3.2 Podłączanie wielu diod RGB

Do jednego Arduino możemy podłączyć wiele tradycyjnych diod RGB — każda potrzebuje swoich pinów. Poniżej przykład z dwiema diodami na pinach 3, 5, 6 oraz 9, 10, 11:

<Schematic
  src="/img/lekcje/14.16-schemat-dwie-diody-rgb.jpg"
  caption="Dwie diody RGB podłączone do Arduino — każda na osobnych pinach PWM."
  alt="Schemat Fritzing: dwie diody RGB podłączone do pinów 3,5,6 i 9,10,11"
  width={700}
  height={500}
/>

<Code lang="cpp" file="rgb-dwie-diody.ino">
```cpp
// Definicja wyprowadzeń pierwszej diody
const byte czerwona = 3;
const byte zielona = 5;
const byte niebieska = 6;

// Definicja wyprowadzeń drugiej diody
const byte czerwona2 = 9;
const byte zielona2 = 10;
const byte niebieska2 = 11;

void setup() {
  pinMode(czerwona, OUTPUT);   // Konfiguracja wyprowadzeń jako wyjścia
  pinMode(zielona, OUTPUT);
  pinMode(niebieska, OUTPUT);
  pinMode(czerwona2, OUTPUT);
  pinMode(zielona2, OUTPUT);
  pinMode(niebieska2, OUTPUT);
}

void loop() {
  digitalWrite(czerwona, HIGH);   // Miganie diodami z użyciem różnych kolorów
  digitalWrite(zielona2, HIGH);
  delay(1000);
  digitalWrite(czerwona, LOW);
  digitalWrite(zielona2, LOW);
  digitalWrite(niebieska, HIGH);
  digitalWrite(czerwona2, HIGH);
  delay(1000);
  digitalWrite(niebieska, LOW);
  digitalWrite(czerwona2, LOW);
}
```
</Code>

<Callout type="note" title="Limity pinów PWM w Arduino UNO">
Arduino UNO posiada tylko **6 pinów PWM**: 3, 5, 6, 9, 10, 11. Dwie diody RGB zajmują wszystkie sześć — przy trzech tradycyjnych diodach RGB brakowałoby pinów. To jeden z powodów, dla których diody **WS2812** są praktyczniejsze przy większych projektach.
</Callout>

### 3.3 Mieszanie kolorów za pomocą PWM

Funkcja `analogWrite(pin, wartość)` ustawia wypełnienie PWM w zakresie 0–255. Możemy dzięki temu płynnie regulować jasność każdego kanału i mieszać kolory. Poniższy szkic płynnie zmienia kolory obu diod w pętli:

<Schematic
  src="/img/lekcje/14.17-schemat-diody-rgb-pwm.jpg"
  caption="Układ z dwiema diodami RGB gotowy do mieszania kolorów przez PWM."
  alt="Schemat Fritzing dla płynnej zmiany kolorów dwóch diod RGB"
  width={700}
  height={500}
/>

<Code lang="cpp" file="rgb-mieszanie-kolorow.ino">
```cpp
// Definicja wyprowadzeń pierwszej diody
const byte czerwona = 3;
const byte zielona = 5;
const byte niebieska = 6;

// Definicja wyprowadzeń drugiej diody
const byte czerwona2 = 9;
const byte zielona2 = 10;
const byte niebieska2 = 11;

void setup() {
  pinMode(czerwona, OUTPUT);   // Konfiguracja wyprowadzeń jako wyjścia
  pinMode(zielona, OUTPUT);
  pinMode(niebieska, OUTPUT);
  pinMode(czerwona2, OUTPUT);
  pinMode(zielona2, OUTPUT);
  pinMode(niebieska2, OUTPUT);
}

void loop() {
  int zmiana = 0;

  for (zmiana = 0; zmiana < 255; zmiana++) { // Płynna zmiana kolorów
    analogWrite(czerwona, 0);
    analogWrite(zielona, zmiana);
    analogWrite(niebieska, 255 - zmiana);

    analogWrite(czerwona2, zmiana);
    analogWrite(zielona2, 255 - zmiana);
    analogWrite(niebieska2, 0);

    delay(10); // Krótkie opóźnienie, aby efekt był widoczny dla ludzkiego oka
  }
}
```
</Code>

```cpp
    analogWrite(niebieska, 255 - zmiana);

    analogWrite(czerwona2, zmiana);
    analogWrite(zielona2, 255 - zmiana);
    analogWrite(niebieska2, zmianaLosowa);

    delay(10);
  }
}
```
</Code>

Każda dioda WS2812 zawiera miniaturowy sterownik, który:
1. Odbiera dane z Arduino przez **jeden przewód danych**.
2. Odczytuje własny kolor (24 bity: 8 bitów R, 8 G, 8 B).
3. **Przekazuje dalej** pozostałe dane do następnej diody w szeregu.

Dzięki temu do sterowania 8 (lub 800) diod wystarczy **jeden pin Arduino**.

<Expandable title="Głębiej: jak fizycznie wygląda protokół WS2812 — bit po bicie" heading="####">
Dlaczego do WS2812 trzeba używać biblioteki zamiast zwykłego `digitalWrite()`? Bo protokół jest **niewiarygodnie wymagający czasowo** — różnica między bitem `0` a bitem `1` to ułamek mikrosekundy.

Protokół WS2812 koduje bity przez **długość impulsu wysokiego** w pojedynczym cyklu trwającym `1,25 µs`:

<Table
  caption="Kodowanie bitów w WS2812"
  headers={["Bit", "Stan wysoki", "Stan niski", "Łącznie"]}
  rows={[
    ["0", "ok. 0,35 µs", "ok. 0,90 µs", "1,25 µs"],
    ["1", "ok. 0,70 µs", "ok. 0,55 µs", "1,25 µs"],
    ["Reset (latch)", "—", "> 50 µs ciągłego LOW", "—"],
  ]}
/>

Każda dioda potrzebuje **24 bitów** (8 G + 8 R + 8 B — kolejność GRB to nie pomyłka, tak działa WS2812). Linijka 8 diod to **192 bity**, czyli `192 × 1,25 µs ≈ 240 µs` na pełną aktualizację.

`digitalWrite()` w Arduino trwa około **5 µs** — to czterokrotnie dłużej niż cały cykl jednego bitu. **Niemożliwe jest** wygenerowanie tego sygnału klasycznymi funkcjami. Biblioteka **Adafruit NeoPixel** używa precyzyjnie pomierzonych pętli w asemblerze i wyłącza przerwania na czas wysyłania, żeby `millis()` ani inne timery nie zaburzyły taktu.

Dlatego podczas `linijka.show()` wszystkie przerwania są zablokowane — i dlatego `delay()` opartego na `millis()` nie powinieneś używać tuż przed `show()` w precyzyjnych systemach czasu rzeczywistego.
</Expandable>

### 4.1 Podłączenie diod WS2812

Moduł linijki WS2812 (8 diod) mocujemy w płytce stykowej tak, aby wygodnie doprowadzić do niego trzy przewody: zasilanie, masę i sygnał sterujący.  
Masę łączymy z **GND**, zasilanie **+5V** z magistralą +5V, a **przewód danych (DIN)** z pinem A0 Arduino.

Najważniejsze jest czytanie oznaczeń bezpośrednio na module. Różne linijki WS2812 mogą wyglądać podobnie, ale mieć inaczej ułożone wyprowadzenia. Nie kieruj się więc samą kolejnością pinów na zdjęciu — szukaj opisów typu `GND`, `5V`, `VCC`, `VIN`, `DIN` oraz czasem `DOUT`.

Podłączaj układ w bezpiecznej kolejności:

1. Odłącz Arduino od USB i zasilania.
2. Włóż linijkę WS2812 w płytkę stykową.
3. Połącz **GND** modułu z masą układu.
4. Połącz pin zasilania modułu z szyną **+5V**.
5. Wstaw kondensator elektrolityczny około **100 µF** między **+5V** i **GND** możliwie blisko modułu.
6. Połącz pin A0 Arduino z wejściem **DIN** przez rezystor z zakresu **300–500 Ω**.
7. Dopiero na końcu podłącz Arduino do komputera.

<Callout type="warning" title="Nie pomyl DIN z DOUT">
Sygnał z Arduino musi trafić do wejścia **DIN** pierwszej diody. Pin **DOUT** służy do przekazywania danych dalej, do następnej linijki lub taśmy. Jeśli podłączysz Arduino do `DOUT`, diody najczęściej nie zareagują.
</Callout>

<Callout type="tip" title="Rezystor i kondensator chronią układ">
Rezystor w linii danych tłumi krótkie zakłócenia na przewodzie sygnałowym. Jeśli nie masz rezystora 470 Ω, możesz użyć wartości zbliżonej z zakresu 300–500 Ω; dwa rezystory 1 kΩ połączone równolegle dadzą około 500 Ω. Kondensator 100 µF między +5V i GND pomaga przy nagłych zmianach poboru prądu, np. gdy wiele diod jednocześnie świeci jasno.
</Callout>

## 6. Kiedy diody tradycyjne, a kiedy programowalne?

<Table
  caption="Porównanie tradycyjnych diod RGB i diod WS2812"
  headers={["Cecha", "Tradycyjna RGB", "WS2812 (programowalna)"]}
  rows={[
    ["Liczba pinów Arduino", "3 piny na diodę", "1 pin na całą linijkę"],
    ["Rezystory", "Konieczne (3 szt. na diodę)", "Zalecany rezystor w linii danych"],
    ["Adresowanie diod", "Nie — wszystkie reagują tak samo", "Tak — każda niezależnie"],
    ["Biblioteka", "Nie potrzeba", "Wymagana (NeoPixel)"],
    ["Koszt", "Niski", "Wyższy"],
    ["Kiedy używać", "1–2 diody, prosta sygnalizacja", "Wiele diod, animacje, efekty wizualne"],
  ]}
/>

Jeśli projekt wymaga tylko jednej lub dwóch diod do sygnalizacji stanu — tradycyjna RGB jest prostsza i tańsza. Jeśli jednak zależy nam na wielu diodach RGB lub efektach świetlnych, WS2812 jest zdecydowanie wygodniejszym wyborem.

<Expandable title='Głębiej: korekcja gamma — dlaczego `analogWrite(64)` nie jest „połową jasności"' heading="####">
Programujesz płynne rozjaśnianie LED od `0` do `255` w równych krokach co `10`. Oczekujesz liniowego efektu — a tymczasem oko widzi, że dioda **gwałtownie skacze** w pierwszej połowie i ledwo się zmienia w drugiej. Dlaczego?

Powód leży w **nieliniowości ludzkiego wzroku** — opisuje ją tzw. **krzywa gamma**. Nasze oko jest dużo bardziej czułe na zmiany w zakresie niskiej jasności niż wysokiej. Dlatego percepcyjna „połowa jasności" odpowiada wartości PWM około **`64`–`73`**, a nie `128`.

Rozwiązanie to **korekcja gamma** — zamiast wysyłać `wartosc` bezpośrednio do `analogWrite()`, transformujesz ją przez potęgę (zwykle `γ = 2,2` lub `2,8`):

```cpp
byte gammaKorekta(byte wartosc) {
  float znormalizowana = wartosc / 255.0;
  float skorygowana = pow(znormalizowana, 2.2);
  return (byte)(skorygowana * 255);
}

// użycie:
analogWrite(LED, gammaKorekta(linearWartosc));
```

W praktyce zamiast liczyć `pow()` w czasie pracy, używa się **wstępnie obliczonej tablicy 256 wartości** w pamięci PROGMEM. Biblioteka Adafruit NeoPixel ma wbudowane funkcje `gamma8()` i `gamma32()` — wystarczy `linijka.setPixelColor(i, linijka.gamma32(linijka.Color(r, g, b)))`.

Bez korekcji gamma efekt płynnej tęczy lub oddychającej diody wygląda „kanciasto". Z korekcją — naprawdę płynnie. To pierwszy poziom dobrego efektu świetlnego.
</Expandable>

## Podsumowanie

Tradycyjna dioda RGB wymaga trzech pinów PWM i trzech rezystorów — za to jest prosta i nie wymaga żadnej biblioteki. Przez `analogWrite()` w zakresie 0–255 na każdym kanale R, G, B możemy uzyskać dowolny kolor świetlny. Dioda programowalna WS2812 idzie o krok dalej: wbudowany sterownik pozwala adresować każdą diodę z osobna przez jeden przewód danych i bibliotekę NeoPixel. Kluczowe do zapamiętania: zawsze po `setPixelColor()` wywołuj `show()`, inaczej zmiany nie trafią do diod. Przy intensywnych efektach świetlnych na wielu diodach WS2812 korzystaj z zewnętrznego zasilania 5 V — każda dioda przy pełnej bieli pobiera nawet 60 mA.
