W tej lekcji nauczymy się omijać jedno z największych ograniczeń funkcji `delay()` — **blokowanie całego programu**. Poznasz funkcję `millis()`, która działa jak wbudowany stoper i pozwala Arduino wykonywać kilka zadań „jednocześnie" — bez zatrzymywania pętli `loop()`.

## 1. Problem z delay()

Funkcja `delay()` jest chętnie używana przez początkujących, bo jest prosta i intuicyjna. Jednak ma poważną wadę — **całkowicie wstrzymuje działanie programu** na zadany czas.

Pojedyncze miganie diody LED nie sprawia trudności:

<Code lang="cpp" file="led-delay-1.ino">
```cpp
const byte LED1pin = 3;

void setup()
{
  pinMode(LED1pin, OUTPUT);
}

void loop()
{
  digitalWrite(LED1pin, HIGH); // włącz LED
  delay(1000);                 // czekaj 1 sekundę
  digitalWrite(LED1pin, LOW);  // wyłącz LED
  delay(1000);                 // czekaj 1 sekundę
}
```
</Code>

<Photo
  file="21.00.02-petla-led1-1000ms.gif"
  caption="Zawartość pętli loop() dla jednej diody LED migającej co 1000 ms."
  alt="Animacja ilustrująca wykonywanie pętli loop() z delay(1000)"
/>

Problem pojawia się, gdy chcemy migać **dwiema diodami z różnymi interwałami** — na przykład LED1 co 1 sekundę, a LED2 co 500 ms:

<Code lang="cpp" file="led-delay-2.ino">
```cpp
const byte LED1pin = 3;
const byte LED2pin = 4;

void setup()
{
  pinMode(LED1pin, OUTPUT);
  pinMode(LED2pin, OUTPUT);
}

void loop()
{
  // Pierwsza dioda
  digitalWrite(LED1pin, HIGH);
  delay(1000);
  digitalWrite(LED1pin, LOW);
  delay(1000);

  // Druga dioda — uruchamia się DOPIERO po zakończeniu pierwszego bloku
  digitalWrite(LED2pin, HIGH);
  delay(500);
  digitalWrite(LED2pin, LOW);
  delay(500);
}
```
</Code>

<Photo
  file="21.00.03-petla-led1-led2-sekwencyjnie.gif"
  caption="Przy użyciu delay() diody migają kolejno (sekwencyjnie), nie jednocześnie."
  alt="Animacja pokazująca sekwencyjne wykonanie dwóch bloków delay() zamiast równoległego migania"
/>

Arduino wykonuje wszystkie instrukcje z pętli `loop()` linijka po linijce. W danym momencie mikroprocesor może zająć się tylko jedną operacją. Dopóki trwa `delay()`, nic innego nie może się wydarzyć — żaden przycisk nie zostanie odczytany, żaden czujnik nie będzie sprawdzony.

<Callout type="warning" title="Kiedy delay() jest problemem?">
`delay()` można stosować tylko wtedy, gdy jesteś w pełni świadomy, że przez cały czas jego działania program będzie zablokowany. Przy prostych szkicach to bywa akceptowalne — jednak gdy Arduino ma reagować na zdarzenia (przycisk, czujnik, UART) lub wykonywać kilka zadań równolegle, `delay()` staje się przeszkodą.
</Callout>

## 2. Funkcja millis() — wbudowany stoper

W Arduino znajdziemy funkcję `millis()`. Jej działanie najlepiej przyrównać do **stopera, który rusza w momencie uruchomienia Arduino** i nieprzerwanie liczy milisekundy — bez względu na to, co dzieje się w programie.

<Photo
  file="21.00.04-stoper-millis-analogia.jpg"
  caption="millis() działa jak wbudowany stoper — odlicza czas od uruchomienia Arduino."
  alt="Zdjęcie stopera jako analogia do działania funkcji millis()"
  width={600}
  hight={400}
/>

Wartość zwracana przez `millis()` jest typu `unsigned long` (32-bitowa, bez znaku) i rośnie do ok. **50 dni**, po czym resetuje się do zera. Najprościej użyć jej tak:

<Code lang="cpp" file="millis-basic.ino">
```cpp
unsigned long aktualnyCzas = 0;

void setup()
{
  Serial.begin(9600);
}

void loop()
{
  aktualnyCzas = millis();      // pobierz aktualny czas w ms
  Serial.println(aktualnyCzas); // wyślij przez UART
  delay(1000);
}
```
</Code>

<Photo
  file="21.00.05-millis-serial-output.gif"
  caption="Monitor portu szeregowego: millis() wyświetla czas w milisekundach od startu Arduino."
  alt="Animacja monitora portu szeregowego pokazująca rosnącą wartość millis()"
/>

<Callout type="note" title="Typ unsigned long">
Zawsze deklaruj zmienne przechowujące wartość `millis()` jako `unsigned long`. Użycie `int` lub `long` może spowodować błędy przepełnienia, gdy licznik przekroczy 32 767 lub 2 147 483 647 ms.
</Callout>

<Expandable title="Głębiej: co dzieje się po przepełnieniu millis()?" heading="####">

`millis()` nie rośnie w nieskończoność. Po około 49,7 dniach licznik typu `unsigned long` osiąga maksymalną wartość i wraca do zera. To normalne zachowanie liczb bez znaku w mikrokontrolerze.

Dlatego nie porównujemy czasu w stylu `if (millis() > start + interwal)`. Taki zapis może zawieść w okolicy przepełnienia. Bezpieczny wzorzec to odejmowanie: `if (aktualnyCzas - zapamietanyCzas >= interwal)`. Arytmetyka `unsigned long` sprawia, że różnica pozostaje poprawna nawet wtedy, gdy licznik zdążył „zawinąć się” przez zero.

W praktyce oznacza to, że dobrze napisany kod z `millis()` może działać tygodniami bez specjalnej obsługi resetu licznika. Warunek jest bezpieczny, o ile wszystkie zmienne czasu mają typ `unsigned long`.

</Expandable>

## 3. Mierzenie różnicy czasu

Sama wartość `millis()` niewiele nam daje. Prawdziwa użyteczność tej funkcji ujawnia się, gdy **porównujemy dwa odczyty** — sprawdzamy, czy od ostatniego zdarzenia minął wystarczający czas.

Algorytm wygląda następująco:
1. Zapamiętaj czas ostatniego zdarzenia (`zapamietanyCzas`).
2. W każdej iteracji `loop()` pobierz aktualny czas.
3. Oblicz różnicę: `roznicaCzasu = aktualnyCzas - zapamietanyCzas`.
4. Jeśli różnica ≥ żądany interwał — wykonaj akcję i zaktualizuj `zapamietanyCzas`.

<Code lang="cpp" file="millis-roznica.ino">
```cpp
unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzas = 0;
unsigned long roznicaCzasu = 0;

void setup()
{
  Serial.begin(9600);
}

void loop()
{
  aktualnyCzas = millis();
  roznicaCzasu = aktualnyCzas - zapamietanyCzas;

  if (roznicaCzasu >= 1000UL) {       // czy minęła 1 sekunda?
    zapamietanyCzas = aktualnyCzas;   // zapamiętaj aktualny czas
    Serial.println(aktualnyCzas);     // wyświetl wynik
  }
}
```
</Code>

<Callout type="note" title="Sufiks UL przy stałych czasowych">
Przyrostek `UL` przy liczbie (np. `1000UL`) informuje kompilator, że stała jest typu `unsigned long`. Bez niego przy dużych wartościach (> 32 767) może dojść do niezamierzonego skrócenia do typu `int`. Stosuj `UL` zawsze, gdy liczba representuje milisekundy.
</Callout>

## 4. Miganie diody LED bez delay()

Teraz zastosujemy ten wzorzec do migania diodą LED. Kluczem jest zapamiętanie **stanu diody** w zmiennej:

<Code lang="cpp" file="led-millis.ino">
```cpp
const byte LED1 = 3;

int stanLED1 = LOW; // aktualny stan diody

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;

void setup()
{
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
}

void loop()
{
  aktualnyCzas = millis();

  // Czy minął interwał dla LED1?
  if (aktualnyCzas - zapamietanyCzasLED1 >= 1000UL)
  {
    zapamietanyCzasLED1 = aktualnyCzas; // zapamiętaj czas przełączenia
    stanLED1 = !stanLED1;               // zmień stan na przeciwny
    digitalWrite(LED1, stanLED1);       // zastosuj nowy stan
  }
}
```
</Code>

<Photo
  file="21.00.07-led-miga-millis.gif"

  width={600}

Program wygląda bardziej rozbudowanie niż z `delay()`, ale zysk jest ogromny — `loop()` wykonuje się bez przerwy i jest gotowa na kolejne zadania.

## 5. Dwie diody — prawdziwa wielozadaniowość

<Photo
  file="21.00.08-dwie-czestotliwosci-porownanie.gif"
  caption="Porównanie: z delay() diody migają sekwencyjnie; z millis() migają niezależnie z własnymi częstotliwościami."
  alt="Animacja porównująca miganie diod LED z delay() i z millis()"
/>

Wystarczy dodać drugi zestaw zmiennych (stan, czas zapamiętany, interwał) i drugi blok `if`, aby obie diody działały całkowicie niezależnie:

<Code lang="cpp" file="dwa-led-millis.ino">
```cpp
const byte LED1 = 3;
const byte LED2 = 4;

int stanLED1 = LOW;
int stanLED2 = LOW;

unsigned long miganieLED1 = 1000; // interwał diody 1: 1 sekunda
unsigned long miganieLED2 = 200;  // interwał diody 2: 0,2 sekundy

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;
unsigned long zapamietanyCzasLED2 = 0;

void setup()
{
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
  pinMode(LED2, OUTPUT);
}

void loop()
{
  aktualnyCzas = millis();

  // Zadanie 1: LED1 miga co 1 sekundę
  if (aktualnyCzas - zapamietanyCzasLED1 >= miganieLED1)
  {
    zapamietanyCzasLED1 = aktualnyCzas;
    stanLED1 = !stanLED1;
    digitalWrite(LED1, stanLED1);
  }

  // Zadanie 2: LED2 miga co 200 ms
  if (aktualnyCzas - zapamietanyCzasLED2 >= miganieLED2)
  {
    zapamietanyCzasLED2 = aktualnyCzas;
    stanLED2 = !stanLED2;
    digitalWrite(LED2, stanLED2);
  }
}
```
</Code>

<Photo
  file="21.00.10-dwa-led-rozne-czestotliwosci.gif"
  caption="Dwie diody LED migają jednocześnie z różnymi częstotliwościami — żadna nie przeszkadza drugiej."
  alt="Animacja dwóch diod LED migających niezależnie dzięki millis()"
/>

To jest serce wielozadaniowości w Arduino: każde zadanie ma własny zegar (`zapamietanyCzas`) i własny interwał — i sprawdza tylko siebie w każdej iteracji `loop()`.

## 6. Sterowanie przyciskiem

Wzorzec `millis()` łatwo łączy się z odczytem wejść. Poniższy szkic zmienia prędkość migania LED1 w zależności od stanu przycisku, a LED2 miga z niezmiennym rytmem:

<Code lang="cpp" file="dwa-led-przycisk.ino">
```cpp
const byte LED1 = 3;
const byte LED2 = 4;
const byte PRZYCISK = 2;

int stanLED1 = LOW;
int stanLED2 = LOW;

unsigned long miganieLED1 = 1000;
unsigned long miganieLED2 = 200;

unsigned long aktualnyCzas = 0;
unsigned long zapamietanyCzasLED1 = 0;
unsigned long zapamietanyCzasLED2 = 0;

void setup()
{
  Serial.begin(9600);
  pinMode(LED1, OUTPUT);
  pinMode(LED2, OUTPUT);
  pinMode(PRZYCISK, INPUT_PULLUP); // wewnętrzny rezystor podciągający
}

void loop()
{
  aktualnyCzas = millis();

  // Odczyt przycisku zmienia interwał LED1
  if (digitalRead(PRZYCISK) == LOW)
  {
    miganieLED1 = 100;  // przycisk wciśnięty: szybkie miganie
  }
  else
  {
    miganieLED1 = 2000; // przycisk zwolniony: wolne miganie
  }

  // Zadanie 1: LED1 z dynamicznym interwałem
  if (aktualnyCzas - zapamietanyCzasLED1 >= miganieLED1)
  {
    zapamietanyCzasLED1 = aktualnyCzas;
    stanLED1 = !stanLED1;
    digitalWrite(LED1, stanLED1);
  }

  // Zadanie 2: LED2 stały rytm
  if (aktualnyCzas - zapamietanyCzasLED2 >= miganieLED2)
  {
    zapamietanyCzasLED2 = aktualnyCzas;
    stanLED2 = !stanLED2;
    digitalWrite(LED2, stanLED2);
  }
}
```
</Code>

<Photo
  file="21.00.11-dwa-led-przycisk.gif"
  caption="Wciśnięcie przycisku natychmiast zmienia tempo migania LED1 — LED2 nie jest zakłócana."
  alt="Animacja: przycisk zmienia częstotliwość migania pierwszej diody LED bez wpływu na drugą"
/>

Zwróć uwagę: odczyt `digitalRead(PRZYCISK)` dzieje się w **każdej** iteracji `loop()` — natychmiastowa reakcja na naciśnięcie byłaby niemożliwa z `delay()`.

## 7. Ćwiczenia

<Task title="Zadanie — trzy niezależne diody LED" estimate="15 min">
Podłącz trzy diody LED do pinów 3, 4 i 5. Użyj `millis()`, żeby migały z różnymi interwałami:
- LED1: co **200 ms**
- LED2: co **700 ms**
- LED3: co **1500 ms**

Żadna dioda nie może wpływać na rytm pozostałych. Nie używaj `delay()`.
</Task>

<Task title="Zadanie — timer odliczający czas" estimate="20 min">
Napisz program, który:
1. Po wciśnięciu przycisku (pin 2, `INPUT_PULLUP`) uruchamia **10-sekundowy timer**.
2. W Monitorze portu szeregowego co sekundę wypisuje, ile sekund zostało do końca.
3. Po upłynięciu 10 sekund włącza diodę LED (pin 13) na 3 sekundy, po czym ją wyłącza.
4. Nowe wciśnięcie przycisku w trakcie odliczania **resetuje** timer.

Wskazówka: użyj jednej zmiennej `zapamietanyStart` do przechowywania momentu wciśnięcia przycisku.
</Task>

<MiniProject title="Projekt końcowy — stacja świetlna z przyciskiem stop" estimate="30 min">
Zbuduj układ z dwiema diodami LED i przyciskiem:
- **Tryb normalny**: LED1 miga co 500 ms, LED2 miga co 1200 ms.
- **Wciśnięcie przycisku**: obie diody gasną i przez **5 sekund** układ jest „zamrożony" (żadne LED nie miga).
- Po 5 sekundach **automatycznie** wraca do trybu normalnego.

Uwaga: podczas „zamrożenia" przycisk nie może być ponownie aktywowany — odblokowanie następuje wyłącznie po upływie czasu.
</MiniProject>

## Podsumowanie

Funkcja **`millis()`** zwraca liczbę milisekund od uruchomienia Arduino (typ `unsigned long`) i **nigdy nie blokuje** programu — to jej kluczowa przewaga nad `delay()`. Wzorzec wielozadaniowości sprowadza się do trzech elementów: zmienna `zapamietanyCzas`, porównanie `millis() - zapamietanyCzas >= interwał` i aktualizacja `zapamietanyCzas` po każdym zdarzeniu. Każde niezależne zadanie dostaje własny zegar i własny interwał — `loop()` działa nieprzerwalnie, reagując na wszystkie zdarzenia (przyciski, czujniki, UART) bez żadnych opóźnień. Pamiętaj: zmienne przechowujące czas zawsze deklaruj jako `unsigned long`, a stałe interwałów zapisuj z sufiksem `UL`.
