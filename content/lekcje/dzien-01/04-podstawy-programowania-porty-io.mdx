W tej lekcji piszemy pierwsze działające programy na Arduino. Zaczniemy od struktury szkicu, a skończymy na symulacji świateł drogowych sterowanej przyciskiem. Po drodze poznasz wszystkie podstawowe funkcje wejścia-wyjścia: `pinMode()`, `digitalWrite()`, `digitalRead()` i `delay()`.

## 1. Podstawowy szkielet programu Arduino

Każdy program komputerowy to zbiór rozkazów. W języku C/C++ (który stosujemy w Arduino) program wygląda tak:

```cpp
int main() {
  // Zawartość programu
}
```

Arduino upraszcza ten zapis do dwóch specjalnych funkcji:

<Code lang="cpp" file="szkielet.ino">
```cpp
void setup() {
  // Instrukcje, które wykonają się jeden raz
}

void loop() {
  // Instrukcje, które będą wykonywały się w koło (w pętli)
}
```
</Code>

`setup()` uruchamia się raz — zaraz po włączeniu lub zresetowaniu Arduino. Umieszczamy tu wszystko, co musi się zainicjować przed głównym działaniem programu.

`loop()` to pętla nieskończona — po wykonaniu ostatniej linii wraca do początku i powtarza się bez końca, dopóki Arduino ma zasilanie.

<Callout type="note" title="Komentarze w kodzie">
Tekst po `//` to komentarz — kompilator go ignoruje. Pisz komentarze po polsku lub angielsku, żeby za tydzień móc zrozumieć własny kod.
</Callout>

## 2. Funkcje — co oznaczają te zapisy?

Funkcja to wydzielony blok rozkazów, który można wywołać w dowolnym miejscu programu. Dzięki temu nie trzeba kopiować tego samego kodu w kółko — wystarczy napisać nazwę funkcji z nawiasami.

`setup()` i `loop()` to funkcje wbudowane w środowisko Arduino. Sam będziesz pisać własne funkcje w dalszej części kursu.

Słowo `void` przed nazwą oznacza, że funkcja nie zwraca żadnej wartości — po prostu wykonuje zadanie i kończy działanie.

## 4. Wyjścia w praktyce — dioda LED

Żeby zapalić diodę LED, musimy:
1. Powiedzieć Arduino, że dany pin będzie **wyjściem** (`pinMode`).
2. Ustawić na nim stan wysoki (`digitalWrite`).

<Schematic
  src="/img/lekcje/dzien-01/04.02-dioda-led-schemat.png"
  caption="Podłączenie diody LED do pinu 8 przez rezystor 330 Ω."
  alt="Schemat podłączenia diody LED i rezystora do Arduino UNO"
  width={600}
  height={400}
/>

<Callout type="hazard" title="Rezystor jest obowiązkowy">
Bez rezystora przez diodę LED popłynie za duży prąd i zniszczy ją — albo uszkodzi pin Arduino. Dla diod 5 mm stosuj rezystor 220–330 Ω.
</Callout>

Program, który zapala diodę podłączoną do pinu 8:

<Code lang="cpp" file="dioda-wlaczona.ino">
```cpp
void setup() {
  pinMode(8, OUTPUT);       // Konfiguracja pinu 8 jako wyjście
  digitalWrite(8, HIGH);   // Włączenie diody
}

void loop() {
}
```
</Code>

`pinMode(numer_pinu, tryb)` — konfiguruje pin. Tryb `OUTPUT` to wyjście, `INPUT` to wejście.

`digitalWrite(numer_pinu, stan)` — ustawia stan pinu: `HIGH` (5 V) lub `LOW` (0 V).

## 5. Opóźnienia w programie — miganie diodą

Funkcja `delay(ms)` wstrzymuje wykonanie programu na podaną liczbę milisekund (`1000 ms = 1 s`). Bez opóźnień Arduino przełączałoby pin miliony razy na sekundę — oko nie zdążyłoby tego zauważyć.

<Code lang="cpp" file="miganie-led.ino">
```cpp
void setup() {
  pinMode(8, OUTPUT);   // Konfiguracja pinu 8 jako wyjście
}

void loop() {
  digitalWrite(8, HIGH);   // Włączenie diody
  delay(1000);             // Odczekanie 1 sekundy
  digitalWrite(8, LOW);    // Wyłączenie diody
  delay(1000);             // Odczekanie 1 sekundy
}
```
</Code>

Wgraj program i obserwuj, jak dioda miga co sekundę. Zmień `1000` na mniejsze wartości i sprawdź, przy jakim opóźnieniu miganie staje się niewidoczne dla oka.

<Task title="Zadanie 1.1" estimate="10 min">
Znajdź najmniejszą wartość `delay()`, przy której jesteś jeszcze w stanie dostrzec miganie diody. Następnie podłącz drugą diodę do pinu 9 i napisz program, w którym diody migają na zmianę — gdy jedna świeci, druga jest wyłączona.
</Task>

## 6. Wejścia układu — instrukcja warunkowa i przycisk

Do odczytu stanu przycisku (lub innego sygnału wejściowego) używamy `digitalRead()`. Wcześniej trzeba skonfigurować pin jako wejście przez `pinMode`.

<Schematic
  src="/img/lekcje/dzien-01/04.03-przycisk-schemat.png"
  caption="Podłączenie przycisku chwilowego do pinu 7 z wykorzystaniem INPUT_PULLUP."
  alt="Schemat podłączenia przycisku do Arduino UNO z rezystorem podciągającym"
  width={600}
  height={400}
/>

### Tryb INPUT_PULLUP

Zamiast zewnętrznego rezystora podciągającego używamy wbudowanego rezystora Arduino:

```cpp
pinMode(7, INPUT_PULLUP);
```

Gdy przycisk **nie jest wciśnięty** → pin ma stan `HIGH` (5 V, rezystor ciągnie do zasilania).
Gdy przycisk **jest wciśnięty** → pin jest zwierany do masy → stan `LOW` (0 V).

Dlatego sprawdzamy `== LOW` jako warunek wciśnięcia.

### Instrukcja warunkowa if/else

<Code lang="cpp" file="przycisk-dioda.ino">
```cpp
void setup() {
  pinMode(8, OUTPUT);          // Dioda jako wyjście
  pinMode(7, INPUT_PULLUP);    // Przycisk jako wejście
  digitalWrite(8, LOW);        // Wyłączenie diody
}

void loop() {
  if (digitalRead(7) == LOW) {   // Jeśli przycisk wciśnięty
    digitalWrite(8, HIGH);       // Włącz diodę
  } else {                       // Jeśli warunek nie jest spełniony
    digitalWrite(8, LOW);        // Wyłącz diodę
  }
}
```
</Code>

Instrukcja `if (warunek) { ... } else { ... }` sprawdza warunek. Jeśli jest prawdziwy, wykonuje pierwszy blok; w przeciwnym razie — blok po `else`. Część `else` jest opcjonalna.

<Task title="Zadanie 1.2" estimate="10 min">
Zmień program tak, żeby dioda zapalała się po wciśnięciu przycisku i gasła po jego puszczeniu — ale tym razem bez bloku `else`. Czy program działa tak samo?
</Task>

## 7. Przykład — włącznik światła z czasomierzem

Chcemy, żeby wciśnięcie przycisku włączyło diodę na 10 sekund, a potem automatycznie ją wyłączyło:

<Code lang="cpp" file="wlacznik-czasomierz.ino">
```cpp
void setup() {
  pinMode(8, OUTPUT);          // Dioda jako wyjście
  pinMode(7, INPUT_PULLUP);    // Przycisk jako wejście
  digitalWrite(8, LOW);        // Wyłączenie diody
}

void loop() {
  if (digitalRead(7) == LOW) {   // Jeśli przycisk wciśnięty
    digitalWrite(8, HIGH);       // Włącz diodę
    delay(10000);                // Czekaj 10 sekund
    digitalWrite(8, LOW);        // Wyłącz diodę
  }
}
```
</Code>

<Callout type="warning" title="Blokujące delay()">
Przez 10 sekund, gdy trwa `delay()`, Arduino nie reaguje na nic innego — przyciski, czujniki, komunikacja. To ograniczenie opóźnień blokujących. W lekcjach o `millis()` poznasz nieblokujące podejście.
</Callout>

## 8. Przykład — symulacja świateł drogowych

Trzy diody LED (czerwona na pin 10, żółta/pomarańczowa na pin 9, zielona na pin 8) i przycisk na pin 7. Najpierw inicjalizujemy piny:

<Schematic
  src="/img/lekcje/dzien-01/04.04-swiatla-drogowe-schemat.png"
  caption="Schemat układu: trzy diody LED i przycisk podłączone do Arduino UNO."
  alt="Schemat podłączenia trzech diod LED (czerwona, zolta, zielona) i przycisku do Arduino"
  width={700}
  height={450}
/>

<Code lang="cpp" file="swiatla-inicjalizacja.ino">
```cpp
void setup() {
  pinMode(10, OUTPUT);   // Dioda czerwona
  pinMode(9, OUTPUT);    // Dioda żółta
  pinMode(8, OUTPUT);    // Dioda zielona

  pinMode(7, INPUT_PULLUP);   // Przycisk

  digitalWrite(10, LOW);   // Wyłączenie diod
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
}

void loop() {
  // Tutaj będzie nasz program
}
```
</Code>

### Automatyczne światła z opóźnieniami

Pierwsza wersja — każdy kolor świeci przez 1 sekundę automatycznie:

<Code lang="cpp" file="swiatla-automatyczne.ino">
```cpp
void setup() {
  pinMode(10, OUTPUT);
  pinMode(9, OUTPUT);
  pinMode(8, OUTPUT);
  pinMode(7, INPUT_PULLUP);
  digitalWrite(10, LOW);
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
}

void loop() {
  digitalWrite(10, LOW);    // Czerwona wył.
  digitalWrite(9, LOW);     // Pomarańczowa wył.
  digitalWrite(8, HIGH);    // Zielona wł.
  delay(1000);

  digitalWrite(10, LOW);
  digitalWrite(9, HIGH);    // Pomarańczowa wł.
  digitalWrite(8, LOW);
  delay(1000);

  digitalWrite(10, HIGH);   // Czerwona wł.
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
  delay(1000);

  digitalWrite(10, HIGH);   // Czerwona + pomarańczowa
  digitalWrite(9, HIGH);
  digitalWrite(8, LOW);
  delay(1000);
}
```
</Code>

## 9. Pętla while

`while (warunek) { ... }` wykonuje blok kodu tak długo, jak warunek jest prawdziwy. Gdy warunek staje się fałszywy, program przechodzi dalej.

Klasyczny przykład: czekaj, aż przycisk zostanie wciśnięty:

```cpp
while (digitalRead(7) == HIGH) {}   // Czekaj na wciśnięcie przycisku
```

Pusta klamra `{}` oznacza, że w pętli nie ma żadnego kodu — program po prostu kręci się w kółko, sprawdzając stan przycisku, aż do momentu jego wciśnięcia.

### Światła drogowe sterowane przyciskiem

Teraz zamiast `delay()` używamy `while()` — każda faza świateł trwa, aż ktoś naciśnie przycisk:

<Code lang="cpp" file="swiatla-przycisk-while.ino">
```cpp
void setup() {
  pinMode(10, OUTPUT);
  pinMode(9, OUTPUT);
  pinMode(8, OUTPUT);
  pinMode(7, INPUT_PULLUP);
  digitalWrite(10, LOW);
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
}

void loop() {
  digitalWrite(10, LOW);
  digitalWrite(9, LOW);
  digitalWrite(8, HIGH);    // Zielona
  while (digitalRead(7) == HIGH) {}   // Czekaj na przycisk

  digitalWrite(10, LOW);
  digitalWrite(9, HIGH);    // Pomarańczowa
  digitalWrite(8, LOW);
  while (digitalRead(7) == HIGH) {}

  digitalWrite(10, HIGH);   // Czerwona
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
  while (digitalRead(7) == HIGH) {}

  digitalWrite(10, HIGH);   // Czerwona + pomarańczowa
  digitalWrite(9, HIGH);
  digitalWrite(8, LOW);
  while (digitalRead(7) == HIGH) {}
}
```
</Code>

### Wersja łączona — opóźnienie + przycisk

Minimalna przerwa (1 sekunda) przed sprawdzaniem przycisku — żeby uniknąć przypadkowego wciśnięcia:

<Code lang="cpp" file="swiatla-delay-while.ino">
```cpp
void setup() {
  pinMode(10, OUTPUT);
  pinMode(9, OUTPUT);
  pinMode(8, OUTPUT);
  pinMode(7, INPUT_PULLUP);
  digitalWrite(10, LOW);
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
}

void loop() {
  digitalWrite(10, LOW);
  digitalWrite(9, LOW);
  digitalWrite(8, HIGH);    // Zielona
  delay(1000);
  while (digitalRead(7) == HIGH) {}

  digitalWrite(10, LOW);
  digitalWrite(9, HIGH);    // Pomarańczowa
  digitalWrite(8, LOW);
  delay(1000);
  while (digitalRead(7) == HIGH) {}

  digitalWrite(10, HIGH);   // Czerwona
  digitalWrite(9, LOW);
  digitalWrite(8, LOW);
  delay(1000);
  while (digitalRead(7) == HIGH) {}

  digitalWrite(10, HIGH);   // Czerwona + pomarańczowa
  digitalWrite(9, HIGH);
  digitalWrite(8, LOW);
  delay(1000);
  while (digitalRead(7) == HIGH) {}
}
```
</Code>

<Task title="Zadanie — rozbudowa świateł" estimate="15 min">
Dodaj do programu świateł drogowych różne czasy opóźnień dla każdej fazy (np. zielona świeci 3 sekundy, żółta 1 sekundę, czerwona 2 sekundy). Następnie zmień program tak, żeby po wciśnięciu przycisku wyświetlał się komunikat w Monitorze portu szeregowego z informacją, na którą fazę właśnie przeszedł.
</Task>

<Expandable title="Dlaczego while() a nie if() do czekania?" heading="###">

`if()` sprawdza warunek **raz** i przechodzi dalej. Jeśli chcesz poczekać na zdarzenie (np. wciśnięcie przycisku), `if()` nie wystarczy — po jednym sprawdzeniu program idzie dalej niezależnie od wyniku.

`while()` sprawdza warunek **w kółko** i zatrzymuje się w miejscu, aż warunek się zmieni. To idealne narzędzie do czekania na zdarzenie. Pętla `while (digitalRead(7) == HIGH) {}` mówi: *kręć się w kółko sprawdzając pin, dopóki jest HIGH — czyli dopóki przycisk nie jest wciśnięty*.

</Expandable>

## Podsumowanie

Każdy szkic Arduino ma dwie obowiązkowe funkcje: `setup()` (jednorazowo) i `loop()` (w nieskończoność). Piny cyfrowe konfiguruje się przez `pinMode()` i steruje nimi przez `digitalWrite()` lub odczytuje przez `digitalRead()`. Tryb `INPUT_PULLUP` pozwala podłączyć przycisk bez zewnętrznego rezystora — wciśnięcie daje `LOW`. Instrukcja `if/else` podejmuje decyzje na podstawie warunku, a `while()` czeka tak długo, jak warunek jest prawdziwy. Łącząc te elementy, zbudowałeś pełny system świateł drogowych sterowany przyciskiem.
